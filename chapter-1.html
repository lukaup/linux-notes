1-01

操作系统概述

一句话核心操作系统是硬件和应用软件之间的“总管家”，负责管理 CPU、内存、磁盘、设备，并给用户提供操作界面。

本节要解决的问题

很多人学 Linux 一上来就背命令，结果越学越乱。先把“操作系统到底在管什么”想明白，后面看到进程、内存、文件、权限，才知道它们各自站在哪一层。

核心概念（小白也能懂）

硬件
CPU、内存、硬盘、网卡、键盘鼠标等看得见摸得着的部分。没有软件，它只是一堆电子元件。
操作系统（OS）
一组系统软件，向下管理硬件，向上给应用程序提供统一接口，让程序不用直接和硬件打交道。
内核（Kernel）
操作系统最核心的部分，直接和硬件打交道，负责进程调度、内存管理、文件系统、设备驱动等。
应用程序
运行在操作系统之上的软件，如浏览器、MySQL、QQ。它们通过系统调用请内核帮忙。
Shell
命令解释器，是用户和内核之间的“翻译官”。你敲 ls，Shell 解释后请内核执行。

拆开讲

可以把一台电脑想成一家公司：硬件是厂房、机器和员工；操作系统是管理层；应用程序是各个业务部门；内核是管理层里真正拍板、分配资源的核心人物。业务部门要用人、用机器，不能直接冲进车间，而要向管理层申请。

操作系统有五大基本功能：处理机管理（决定哪个程序先用 CPU）、存储器管理（分配内存、做虚拟内存）、文件管理（组织目录和文件）、设备管理（驱动键盘、网卡、磁盘）、用户接口（命令行或图形界面）。

常见操作系统分两类：桌面/移动端有 Windows、macOS、Android、iOS、HarmonyOS；服务器端有 Linux、Windows Server、各种 Unix。Linux 在服务器、云计算、大数据、嵌入式领域特别常见。

Linux 的故事要记住三个关键词：Unix（1969 年贝尔实验室，老前辈）、Minix（教学用类 Unix 系统）、Linus Torvalds（1991 年发布 Linux 内核）。Linux 采用 GPL 开源协议，任何人都能使用、修改、再发布，于是长出了成百上千个“发行版”。

命令/操作速查

最容易混的四个概念

概念是什么类比例子
硬件物理设备厂房、机器CPU、内存、硬盘
内核OS 的核心，直接管硬件公司里真正管资源的总经理Linux kernel
发行版内核 + 工具 + 软件 + 包管理器整套装修好的公司CentOS、Ubuntu、Debian

小白避坑

  • 把“Linux”只当成一个操作系统品牌：严格说 Linux 只是内核，我们平时说的 Linux 多是“发行版”。
  • 以为操作系统就是图形界面：服务器上的 Linux 常常没有桌面，只有命令行，但依然是完整的操作系统。
  • 把内存管理和磁盘管理混为一谈：内存是运行时的“工作台”，磁盘是长期存放的“仓库”。
记忆口诀“硬件在下，内核在中，应用在上；OS 做管家，Shell 做翻译。”

1-02

Linux 初识

一句话核心Linux 是开源、稳定、安全的类 Unix 内核；我们学习的是 CentOS 7 这个发行版，它和 RedHat 企业版高度兼容。

本节要解决的问题

这一节解决三个问题：Linux 从哪来、为什么服务器爱用它、我们到底装哪个版本。别急着敲命令，先把“选型”想清楚。

核心概念（小白也能懂）

开源 / GPL
源代码公开，允许使用、修改、再发布；GPL 要求衍生作品也开源。Linux 因此能被无数公司二次开发。
发行版
把 Linux 内核、GNU 工具、包管理器、桌面环境、常用软件打包在一起的完整系统。
CentOS
基于 RedHat Enterprise Linux（RHEL）源码重新编译的免费发行版，稳定、生态成熟，命令和 RHEL 基本一致。
Ubuntu
基于 Debian，更新快、桌面友好、社区大，服务器上也很常见，使用 apt 包管理。
EOL
End of Life，生命周期结束。CentOS 7 已于 2024-06-30 停止维护，学习仍可用，但生产环境要换 Rocky/Alma/Ubuntu 等。

拆开讲

Linux 的核心优势可以记成四句话：免费开源（成本低、可定制）、稳定可靠（服务器一跑几个月不重启很常见）、安全（权限模型清晰、漏洞修复快）、生态强（云原生、大数据、容器几乎都以 Linux 为底座）。

Linux 的发行版很多，但不用全学。按包管理分两大家族：RedHat 系用 rpm/yum/dnf（CentOS、RHEL、Rocky、Alma、Fedora），Debian 系用 deb/apt（Ubuntu、Debian）。学会一家，另一家的命令对照着就能迁移。

课程选择 CentOS 7，是因为它当年在企业里极常见、资料多、和 RHEL 完全兼容，适合打基础。你完全可以在 CentOS 7 上学会后，把 yum 换成 apt、把配置文件位置换一下，迁移到 Ubuntu。

服务器为什么常不装图形界面？因为图形界面占内存、占 CPU、攻击面更大；服务器更看重稳定和远程管理。命令行看着“原始”，但可脚本化、可批量、可远程，效率极高。

命令/操作速查

常见发行版与适用场景

发行版家族/包管理特点常见场景

小白避坑

  • 把 CentOS 7 当成“最新最好”：它已停止维护，学习可以，生产要选替代品。
  • 在 Ubuntu 上照抄 yum 命令：Ubuntu 用 apt，包名也可能不同。
  • 认为“开源=没有版权”：开源要遵守许可证，GPL 有传染性，商用要注意合规。
  • 盲目追求“最新版本”：服务器更看重稳定和兼容，版本要跟业务和生态匹配。
记忆口诀“红帽系 yum，Debian 系 apt；CentOS 学基础，生产看生命周期。”

1-03

虚拟机介绍

一句话核心虚拟机是用软件模拟出来的一台“电脑”，有独立的虚拟 CPU、内存、磁盘、网卡，和宿主机隔离，随时能拍快照回滚。

本节要解决的问题

学 Linux 最怕把本机搞坏。虚拟机让你在一台电脑里再“变”出几台电脑，随便折腾、随时还原，是零基础学习的最佳沙盒。

核心概念（小白也能懂）

宿主机（Host）
真正运行 VMware 的那台物理电脑，比如你的 Windows 笔记本。
客户机（Guest）
虚拟机里安装的操作系统，比如 CentOS 7。
Hypervisor（虚拟化层）
负责把物理资源分配给虚拟机的软件，VMware Workstation 就是 Type 2 型 Hypervisor。
虚拟磁盘
宿主机上的一个大文件（如 .vmdk），虚拟机把它当成自己的硬盘。
ISO 镜像
光盘的电子版，装系统时挂到虚拟光驱上，相当于把安装光盘塞进电脑。

拆开讲

虚拟化不是“模拟一台假电脑”这么简单，它要解决 CPU 指令、内存隔离、磁盘 I/O、网络转发。现代 CPU 提供 VT-x（Intel）或 AMD-V 硬件虚拟化指令，虚拟机才能跑得接近原生速度。

虚拟机最大的价值是隔离和可回滚：你在虚拟机里 rm -rf、改坏配置、装错软件，都不会影响宿主机；拍个快照，几分钟就能回到干净状态。

VMware 有三种常见网络模式：NAT（虚拟机通过宿主机上网，最省事，课程默认）、桥接（虚拟机和宿主机像局域网里的两台独立电脑，各有各的 IP）、仅主机（只能和宿主机通信，不能上外网）。

资源分配要克制：给虚拟机 2 核 CPU、2～4 GB 内存、20～40 GB 磁盘就足够学 Linux。内存不要超过宿主机的一半，否则宿主机和虚拟机都会卡。

命令/操作速查

三种网络模式怎么选

模式虚拟机能否上网局域网其他机器能否访问适用场景
NAT能（借宿主机）默认不能，需端口转发课程学习、只想上网
桥接能（像独立电脑）能（同网段）要让手机/其他电脑访问虚拟机服务
仅主机不能不能（仅宿主机）做隔离实验、内部网络测试

小白避坑

  • BIOS 里没开 VT-x/AMD-V，VMware 会报“此主机支持 Intel VT-x，但 Intel VT-x 处于禁用状态”。
  • 给虚拟机分配了全部内存，宿主机自己卡死。
  • NAT 模式下直接让局域网同事访问虚拟机 IP：需要配置端口转发，或改用桥接。
  • 把虚拟机磁盘文件当普通文件随便移动/删除，导致虚拟机打不开。
记忆口诀“宿主是真机，客户是虚拟；NAT 借网，桥接独立，仅主机自闭。”

3 分钟自测

Q1宿主机和客户机分别指什么？
答：宿主机是运行虚拟化软件的物理机；客户机是虚拟机里安装的操作系统。
Q2NAT 和桥接最大的区别是什么？
答：NAT 由宿主机做地址转换，虚拟机藏在宿主机后面；桥接让虚拟机像局域网里一台独立电脑，有独立 IP。
Q3为什么学习 Linux 建议用虚拟机？
答：隔离、安全、可拍快照回滚，不怕把本机搞坏。

1-04

安装 VMware Workstation 虚拟化软件

一句话核心安装 VMware Workstation 分三步：确认硬件虚拟化已开启 → 安装软件 → 检查虚拟网卡 VMnet1/VMnet8 正常。

本节要解决的问题

虚拟机软件是“造电脑的机器”。这一节把工具装好，下一节才能开始装 CentOS。安装本身不难，难在虚拟化开关和网络组件。

核心概念（小白也能懂）

VMware Workstation Pro
Windows/Linux 上常用的 Type 2 虚拟化软件，图形化操作，适合学习和开发。
VMnet1
仅主机模式使用的虚拟网卡。
VMnet8
NAT 模式使用的虚拟网卡，宿主机通过它和虚拟机通信。
虚拟网络编辑器
VMware 里管理 VMnet、NAT 网关、DHCP、端口转发的工具。

拆开讲

安装前先确认 CPU 虚拟化已开启。任务管理器 → 性能 → CPU，看“虚拟化：已启用”。如果显示已禁用，重启进 BIOS，把 Intel VT-x 或 AMD-V 设为 Enabled。

Windows 自带的 Hyper-V、WSL2、内存完整性等功能可能和 VMware 抢虚拟化层。如果 VMware 报错，可在“启用或关闭 Windows 功能”里关闭 Hyper-V（但会影响 WSL2/Docker Desktop，按需取舍），或以管理员身份运行 VMware。

安装路径建议不用中文、不用空格，避免后续脚本和命令行出问题。安装完成后，网络连接里应出现 VMware Network Adapter VMnet1 和 VMnet8；如果没有，打开“虚拟网络编辑器 → 还原默认设置”。

安装完成后先别急着建虚拟机，打开“编辑 → 虚拟网络编辑器”，确认 NAT 模式的子网（例如 192.168.x.0/24）和网关（通常是 x.2）。后面配静态 IP 要用到。

命令/操作速查

安装前后的检查清单

检查项正常表现不正常怎么办
CPU 虚拟化任务管理器显示“已启用”进 BIOS 开启 VT-x/AMD-V
VMware 服务服务列表有 VMware 相关服务且运行修复安装/以管理员启动
虚拟网卡网络连接里有 VMnet1、VMnet8虚拟网络编辑器还原默认设置
NAT 网关虚拟网络编辑器里能看到网关 IP记下来，配静态 IP 要用

动手做

  1. 从 VMware 官网下载 Workstation Pro 安装包（Windows 版）。
  2. 右键“以管理员身份运行”，按向导下一步；接受协议，选择安装路径。
  3. 取消不需要的“增强型键盘驱动”等可选组件（默认即可），点击安装。
  4. 安装完成后重启（如提示），打开 VMware，输入许可证或选择个人免费使用。
  5. 打开“编辑 → 虚拟网络编辑器”，确认 VMnet8 为 NAT 模式，记下子网和网关。

小白避坑

  • 安装包来源不明，捆绑病毒；一定从官网或可信渠道下载。
  • 装完发现没有 VMnet8：多半是虚拟网络组件没装好，用安装包“修复”或还原默认设置。
  • 同时开 Hyper-V 和 VMware，导致虚拟机启动报错或极慢。
  • 把安装路径放在中文目录，个别脚本可能识别异常（不是绝对，但建议避免）。
记忆口诀“先开虚拟化，再装 VMware；网卡 VMnet1/8，NAT 网关要记下。”

1-05

VMware Workstation 中安装 CentOS 7 Linux 操作系统

一句话核心装 CentOS 7 的主线：新建虚拟机 → 挂 ISO → 选“GNOME 桌面/最小安装” → 自动分区 → 设置 root 密码和用户 → 打开网络。

本节要解决的问题

这是第一章最重要的一次动手。装系统时每个选择都会影响后面学习，尤其是软件选择、分区、网络和用户。

核心概念（小白也能懂）

ISO 镜像
CentOS 7 的安装光盘镜像，常用 DVD 版（约 4 GB），包含大量软件包。
软件选择
最小安装（无图形界面，省资源）或 GNOME 桌面（有图形界面，直观但占资源）。
分区
把虚拟硬盘切成 /boot、swap、/ 等区域；学习环境用自动分区即可。
root 用户
Linux 超级管理员，拥有最高权限；密码要记牢。
NAT
课程默认网络模式，虚拟机通过宿主机上网，配置简单。

拆开讲

新建虚拟机时选“自定义（高级）”更清楚每一步；选“典型”更省事。无论哪种，关键只有几个：安装来源选 ISO、客户机系统选 Linux/CentOS 7 64 位、磁盘 20 GB 以上、内存 2 GB 以上、网络 NAT。

进入安装界面后，语言建议选“简体中文”或“English”。软件选择里，零基础可以先选“GNOME 桌面”，看着图形界面更有安全感；但真实服务器多用“最小安装”，后面课程也以命令行为主。两种都能学，建议至少装一次最小安装，逼自己用命令行。

安装位置里如果看到“本地标准磁盘”有感叹号，点进去选中磁盘，选择“自动配置分区”，点“完成”。学习环境不需要手动分 /boot、swap、/，自动分区足够；想练手可以选“我要配置分区”，给 /boot 1 GB、swap 2 GB、/ 剩余。

网络和主机名一定要打开右上角的开关，把主机名改成 centos7 或 hadoop1。如果这里不开，装完系统可能没网，还得回头改配置。

设置 root 密码时，如果密码太简单会点两次“完成”强制确认。建议用“大小写字母+数字+符号”的 8 位以上密码。还可以创建一个普通用户，日常用普通用户，需要时 su - 或 sudo。

macOS 安装 VMware Fusion 并安装虚拟机

一句话核心Mac 上用 VMware Fusion 的思路和 Windows 一样，但 Apple 芯片（M1/M2/M3）不能直接装 x86 的 CentOS 7，需要改用 ARM 版 Linux 或云服务器。

本节要解决的问题

用 Mac 的同学最容易在这一节踩坑：教程是 Intel Mac 时代的，而现在的 Mac 多是 Apple 芯片。先认清芯片，再选方案，别硬装。

核心概念（小白也能懂）

VMware Fusion
macOS 上的 VMware 虚拟化软件，和 Workstation 同门。
Intel Mac
使用 Intel x86_64 CPU 的 Mac，可以较顺利安装 x86 版 CentOS 7。
Apple Silicon
M1/M2/M3 等 ARM 架构芯片，只能原生运行 ARM 版系统；x86 系统需要模拟，性能差且兼容性有限。
UTM
Mac 上基于 QEMU 的虚拟化工具，Apple Silicon 上可运行 ARM Linux。

拆开讲

先看“关于本机 → 芯片”：如果是 Intel，按 Windows 类似的步骤装 CentOS 7 x86_64 即可；如果是 Apple 芯片，不要下载 x86_64 的 CentOS 7 ISO，装上了也可能卡在引导或极慢。

Apple Silicon 的推荐路线：VMware Fusion（ARM 版）+ Ubuntu ARM64，或 UTM + Ubuntu ARM64，或者直接买一台云服务器（阿里云/腾讯云轻量应用服务器）用 SSH 连接。课程命令在 Ubuntu 上大部分通用，少数包管理命令换成 apt 即可。

Fusion 的安装同样是拖拽到 Applications，首次打开需要授权系统扩展。新建虚拟机时选择下载好的 ARM64 ISO，网络默认 NAT 即可。

如果你必须跟着课程用 CentOS 7，最稳的是找一台 Intel 芯片的电脑/旧笔记本，或者用云服务器装 CentOS 7（注意 CentOS 7 已 EOL，云厂商镜像可能下架）。

命令/操作速查

Mac 用户的方案选择

芯片能否装 CentOS 7 x86推荐方案
Intel Mac可以VMware Fusion + CentOS 7 x86_64
Apple Silicon不建议/基本不可行Fusion/UTM + Ubuntu ARM64，或云服务器
不想折腾—直接买云服务器，SSH 登录练习

动手做

  1. 查看“关于本机 → 芯片”，确认 Intel 还是 Apple Silicon。
  2. Intel：下载 VMware Fusion 和 CentOS 7 x86_64 ISO，按向导新建虚拟机。
  3. Apple Silicon：下载 VMware Fusion ARM 版（或 UTM）和 Ubuntu ARM64 ISO。
  4. 新建虚拟机，分配 2 核 CPU、4 GB 内存、20 GB 磁盘，网络 NAT。
  5. 安装完成后，在 macOS 终端执行 ssh 用户名@虚拟机IP 验证远程连接。

  • 下载了 ARM 版 Ubuntu 却用 x86 的安装教程，分区/引导界面可能不同。

远程连接 Linux 系统

一句话核心远程连接的本质是：本机通过 SSH 协议登录到 Linux 的 22 端口；前提是 IP 对、网络通、sshd 正在运行。

本节要解决的问题

真实服务器放在机房，不可能每次接显示器。学会 SSH，你才能在 Windows/Mac 上舒服地操作 Linux，也能把命令复制粘贴。

核心概念（小白也能懂）

SSH
Secure Shell，加密的远程登录协议，默认 22 端口，替代不安全的 telnet。
sshd
Linux 上的 SSH 服务端进程，监听 22 端口，接受远程登录。
NAT 端口转发
把宿主机的某个端口映射到虚拟机的 22 端口，让宿主机/局域网能连进来。
Xshell / FinalShell
Windows 上常用的 SSH 客户端，支持多标签、文件传输、配色。

拆开讲

先确认虚拟机 IP：在 VMware 里登录 CentOS，执行 ip addr，找到 ens33 的 inet 地址，例如 192.168.10.128。然后在宿主机 ping 192.168.10.128，能通再谈 SSH。

NAT 模式下，宿主机通常可以直接访问虚拟机 IP；如果不行，在 VMware“虚拟网络编辑器 → VMnet8 → NAT 设置 → 端口转发”里添加：主机端口 2222 → 虚拟机 IP 22。之后用 ssh -p 2222 用户名@127.0.0.1 连接。

连接命令：ssh 用户名@IP，首次会提示指纹，输入 yes，再输入密码。退出用 exit 或 Ctrl+D。如果改过端口，用 ssh -p 端口 用户名@IP。

常用客户端：Xshell（老牌）、FinalShell（带文件管理和监控）、MobaXterm（功能全）、PuTTY（轻量）、VS Code Remote-SSH（写代码方便）。Mac/Linux 直接用终端 ssh。

命令/操作速查

连不上时按顺序排查

顺序检查项命令/操作常见结果
1虚拟机 IPip addr没有 IP → 网络没开
2宿主机到虚拟机ping 虚拟机IP不通 → NAT/防火墙问题
322 端口ss -lntp | grep 22没监听 → sshd 没启动
4sshd 状态systemctl status sshdinactive → start/enable
5防火墙firewall-cmd --list-all22 未放行 → 放行
6账号密码whoami / passwd密码错/用户不存在

动手做

  1. 在虚拟机里执行 ip addr，记下 IP。
  2. 宿主机 ping 该 IP，确认网络通。
  3. 虚拟机里执行 systemctl status sshd，确保 running；没有则 systemctl start sshd。
  4. 宿主机打开 Xshell/FinalShell/终端，新建 SSH 连接，填 IP、22 端口、用户名。
  5. 首次连接确认指纹，输入密码；看到命令提示符即成功。
  6. 如果 NAT 无法直连，配置端口转发后改用 127.0.0.1:2222 连接。

代码/配置参考

# 虚拟机内：查看 IP 和 SSH 服务
ip addr
systemctl status sshd

# 宿主机：测试网络和端口
ping 192.168.10.128
ssh tom@192.168.10.128

# 改过端口时
ssh -p 2222 tom@192.168.10.128

# 退出
exit

小白避坑

  • 把 ssh -p 和 scp -P 的大小写记反：ssh 是小写 p，scp 是大写 P。
  • 用 127.0.0.1 连虚拟机：这是本机回环地址，不是虚拟机 IP。
  • 以为 ping 通就一定能 SSH：还要看 22 端口和 sshd 状态。
  • 虚拟机挂起后 IP 变了，客户端还连旧 IP。
  • 公司网络限制 22 端口，需要换端口或用 VPN。
记忆口诀“IP 通、端口开、服务跑、账号对——四关过了就能连。”

扩展：Win10 配置 WSL（Ubuntu）环境

一句话核心WSL 是 Windows 内置的 Linux 子系统，WSL2 用轻量虚拟机跑真正的 Linux 内核，适合不想装完整虚拟机的人。

本节要解决的问题

如果你只是想在 Windows 上练命令、跑脚本，WSL 比完整虚拟机更轻、启动更快，还能直接访问 Windows 文件。但它不适合模拟多节点集群。

核心概念（小白也能懂）

WSL
Windows Subsystem for Linux，Windows 10/11 上运行 Linux 的兼容层。
WSL1 vs WSL2
WSL1 做系统调用翻译，兼容性一般；WSL2 用轻量虚拟机跑真 Linux 内核，兼容性和性能更好。
发行版
WSL 可安装 Ubuntu、Debian、Kali 等，命令 wsl --install -d Ubuntu。
/mnt/c
WSL 里访问 Windows C 盘的路径，例如 /mnt/c/Users/你的用户名。

拆开讲

Windows 10 2004+ 或 Windows 11，最简单的方式是以管理员身份打开 PowerShell，执行 wsl --install，它会自动开启所需功能、安装 WSL2 内核和 Ubuntu。重启后按提示设置 Linux 用户名和密码。

如果 wsl --install 不可用，手动开启：dism.exe /online /enable-feature /featurename:Microsoft-Windows-Subsystem-Linux /all /norestart，再开启 VirtualMachinePlatform，重启后 wsl --set-default-version 2，最后从 Microsoft Store 安装 Ubuntu。

WSL2 默认没有 systemd，systemctl 会报错。新版 WSL 可在 /etc/wsl.conf 里加 [boot] systemd=true，然后 wsl --shutdown 重启。学习 systemctl 章节时，建议还是用完整虚拟机。

WSL 的文件系统：Linux 根目录在 Windows 的 \\wsl$\Ubuntu 或 \\wsl.localhost\Ubuntu；Windows C 盘在 WSL 的 /mnt/c。跨文件系统读写大量文件会慢，项目代码建议放在 Linux 文件系统里。

命令/操作速查

WSL 常用命令

命令作用
wsl --install一键安装 WSL2 + 默认 Ubuntu
wsl --install -d Ubuntu指定安装 Ubuntu
wsl -l -v查看已安装发行版和 WSL 版本
wsl --set-default-version 2设置默认使用 WSL2
wsl --shutdown关闭所有 WSL 实例
wsl --unregister Ubuntu卸载某个发行版（数据会丢）

动手做

  1. 以管理员身份打开 PowerShell。
  2. 执行 wsl --install，等待下载安装，按提示重启。
  3. 重启后 Ubuntu 自动启动，设置用户名和密码。
  4. 执行 wsl -l -v，确认 VERSION 为 2。
  5. 执行 sudo apt update && sudo apt upgrade -y 更新软件。
  6. 需要 systemd 时，编辑 /etc/wsl.conf 加 [boot] systemd=true，再 wsl --shutdown。

代码/配置参考

# 管理员 PowerShell
wsl --install
wsl -l -v
wsl --set-default-version 2

# Ubuntu 内
sudo apt update
sudo apt install -y net-tools vim curl
uname -a
cat /etc/os-release

小白避坑

  • 把 WSL 当成完整虚拟机，试图在上面搭 3 节点 Hadoop 集群：网络和 systemd 都不方便。
  • 在 /mnt/c 下跑大量小文件项目，速度很慢。
  • 忘记 Windows 功能没开、虚拟化没开，导致 WSL2 启动失败。
  • 直接 wsl --unregister 卸载，里面的数据全部丢失。
记忆口诀“WSL2 = Windows 里的轻量 Linux；练命令可以，搭集群别难为它。”

扩展：虚拟机快照

一句话核心快照是给虚拟机当前状态拍一张“存档照”，出错可以回滚；它方便，但不能替代独立备份。

本节要解决的问题

学 Linux 一定会改坏配置。快照让你在冒险前先存档，失败了秒回滚。会用快照，学习效率至少翻倍。

核心概念（小白也能懂）

快照（Snapshot）
记录虚拟机某一时刻的磁盘、内存（可选）和设备状态，可回滚到该时刻。
回滚
丢弃快照之后的变化，恢复到快照时刻。
克隆
基于虚拟机/快照复制出一台独立的新虚拟机，常用于搭集群。
快照链
多次快照会形成父子链，快照越多，磁盘占用和维护越复杂。

拆开讲

VMware 里操作：选中虚拟机 → 右键“快照 → 拍摄快照”，填名称和描述（例如“装完 CentOS，网络正常”）。恢复时打开“快照管理器”，选中快照点“转到”。

拍快照的最佳时机：装好系统并配置好网络后（干净基线）、做危险实验前（改分区、改网络、装集群）、升级软件前。不要等系统已经坏了才拍。

快照不是备份：快照文件通常和原虚拟磁盘放在一起，磁盘损坏、误删目录时一起没。重要数据要复制到宿主机另一块盘、移动硬盘或云端。

快照会占用额外磁盘空间，拍太多会拖慢虚拟机。实验完成后可以删除中间快照（VMware 会合并磁盘），但“删除快照”不等于“回滚”，操作前看清提示。

命令/操作速查

快照、克隆、备份的区别

方式作用能否防磁盘损坏典型场景
快照记录状态，随时回滚不能危险实验前存档
克隆复制出独立虚拟机部分可以（另存一份）搭多节点集群
备份独立复制数据到其他介质能重要数据/配置保护

动手做

  1. 先关机或确认系统处于稳定状态（内存快照也可，但占空间）。
  2. VMware 菜单：虚拟机 → 快照 → 拍摄快照。
  3. 填写名称（如“baseline-centos7”）和描述（IP、已装软件）。
  4. 做危险操作；如果失败，打开快照管理器 → 选中快照 → 转到。
  5. 实验成功后，删除不再需要的旧快照，释放磁盘空间。

小白避坑

  • 把快照当备份，结果宿主机磁盘坏了，快照和虚拟机一起丢。
  • 快照太多、链太长，虚拟机启动变慢、磁盘暴涨。
  • 回滚后以为“只是恢复系统”，其实快照之后写的代码/数据也没了。
  • 在虚拟机运行时拍内存快照，文件很大；不需要内存状态时可选“关闭电源时拍摄”。
记忆口诀“动手之前先存档，出事回滚不慌张；快照不是备份，重要数据另存放。”

3 分钟自测

Q1快照和备份最重要的区别是什么？
答：快照依赖原虚拟机存储，通常不能防磁盘损坏；备份是独立副本，能防。
Q2什么时候最适合拍快照？
答：系统干净可用时、做危险操作前、升级前。
Q3快照太多有什么问题？
答：占用大量磁盘、形成长快照链、降低性能、增加管理复杂度。

查看系统版本cat /etc/centos-release确认是不是 CentOS 7
查看内核uname -r内核版本，和发行版版本不是一回事
查看 IPip addr现代系统优先用 ip，不再依赖 ifconfig

易混概念对比

概念 A概念 B区别
内核发行版内核只负责最底层资源管理；发行版=内核+GNU 工具+包管理器+软件
NAT桥接NAT 通过宿主机上网、对外不直接暴露；桥接像局域网里多了一台独立电脑
虚拟机快照备份快照依赖同一份磁盘、方便回滚；备份是独立副本，能防磁盘损坏
susudosu 切换到目标用户（要目标用户密码）；sudo 以 root 权限执行一条命令（要自己的密码）

通关自测

Q1操作系统最主要的四项资源管理是什么？
答：处理机（进程）管理、存储器管理、文件管理、设备管理。
Q2Linux 内核和 Linux 发行版有什么区别？
答：内核是系统核心；发行版在内核外还打包了 GNU 工具、包管理器、桌面/服务器软件等。
Q3NAT 模式下，虚拟机为什么能被宿主机访问，但局域网其他电脑不一定能直接访问？
答：NAT 由 VMware 做地址转换，虚拟机在宿主机后面的私有网络里；需要端口转发才能让外部访问。
Q4远程连接 Linux 前，最少要确认哪三件事？
答：IP 地址正确、网络能 ping 通、sshd 服务在 22 端口监听。
Q5快照能不能代替备份？
答：不能。快照和原磁盘通常在同一存储上，磁盘损坏时一起丢失；重要数据要独立备份。
