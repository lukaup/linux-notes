2-01

Linux 目录结构

一句话核心Linux 只有一棵以 / 为根的目录树，没有 C/D 盘；每个目录都有约定俗成的用途，配置去 /etc，日志去 /var/log，第三方软件去 /opt。

本节要解决的问题

学命令前先认路。否则看到 /etc/sysconfig/network-scripts 这种路径会发懵。把目录结构当成一张“城市地图”，后面找文件就是按地图找地址。

核心概念（小白也能懂）

根目录 /
整个目录树的起点，所有路径都从它往下长。它不等于 root 用户的家目录。
/root
root 用户的家目录，普通用户通常进不去。
/home
普通用户的家目录，如 /home/tom；登录后默认就在这里。
FHS
文件系统层次结构标准，规定各类文件应该放在哪些目录，方便不同发行版保持一致。
一切皆文件
Linux 把设备、进程信息也抽象成文件，例如 /dev/sda、/proc/cpuinfo。

拆开讲

Linux 的目录树是单根的：/ 是唯一顶点，所有磁盘分区、U 盘、网络存储都“挂载”到这棵树的某个目录上。Windows 的 C:、D: 是多根，Linux 不是。

记住几个高频目录：/etc 放系统和软件配置；/var 放经常变化的数据（日志 /var/log、网站 /var/www、数据库 /var/lib）；/home 放普通用户文件；/opt 放第三方大型软件；/tmp 放临时文件（重启可能清空）；/usr 放系统软件和共享资源。

/bin、/sbin、/lib 在现代系统里常是指向 /usr/bin、/usr/sbin、/usr/lib 的软链接，这是为了历史兼容。初学不用纠结，知道“常用命令在 /usr/bin”即可。

/proc 和 /sys 是虚拟文件系统，不占磁盘，里面是内核和进程的实时信息。例如 cat /proc/cpuinfo 看 CPU，cat /proc/meminfo 看内存。

命令/操作速查

必须记住的目录

目录用途小白记忆点

/home普通用户家目录你的文档、下载都在这

小白避坑

  • 把 /root 和 / 搞混：/ 是根，/root 是 root 的家目录。
  • 把配置放到 /home 下：换用户或重装系统就丢了，配置应放 /etc。
  • 随便删 /boot、/etc、/usr：可能导致系统无法启动或命令全失效。
  • 以为 Linux 有 C 盘：Linux 用挂载点，所有存储都挂在 / 下的某个目录。
记忆口诀“配置 etc，日志 var，用户 home，软件 opt，临时 tmp，启动 boot。”

2-02

Linux 命令基础

一句话核心Linux 命令的通用格式是“命令 [选项] [参数]”：命令是动作，选项是做事的方式，参数是动作的对象。

本节要解决的问题

命令看着多，其实语法很统一。掌握这个公式，再学会看帮助，你就能自己摸索没用过的命令，而不是死记硬背。

核心概念（小白也能懂）

命令
一个可执行程序，如 ls、cd、cp。本质上是 /usr/bin 下的文件或 Shell 内置功能。
选项（Option）
调整命令行为，通常以 - 开头，如 -l；长选项用 --，如 --help。
参数（Argument）
命令作用的对象，如文件名、目录名、IP。
提示符
# 表示 root，$ 表示普通用户；提示符后的内容才是你要输入的命令。
PATH
环境变量，告诉 Shell 去哪些目录找命令；找不到就报 command not found。

拆开讲

标准格式：命令 [选项] [参数]。例如 ls -l /etc：ls 是命令，-l 是选项，/etc 是参数。选项和参数、多个参数之间用空格隔开，空格不能省。

短选项可以合并：ls -l -a -h 等价于 ls -lah。长选项通常写作 --all、--human-readable。不同命令的选项含义可能不同，别把 -r 在所有命令里都当成“递归”。

不会用就查帮助：命令 --help 看简要说明，man 命令 看完整手册（q 退出，/ 搜索），info 命令 看更详细文档。英文看不懂没关系，先看 SYNOPSIS（语法）和 OPTIONS（选项）。

命令找不到（command not found）通常是三种原因：拼写错、命令没安装、命令不在 PATH 里。用 which 命令 看能不能找到；刚装好的软件可以用绝对路径运行。

命令/操作速查

命令语法拆解

部分作用例子注意
命令做什么ls、cp、grep区分大小写
短选项调整行为-l、-a、-h可合并为 -lah
长选项调整行为（可读性好）--help、--all通常两个减号
参数对谁做/etc、file.txt空格分隔；含空格要引号
重定向/管道改变输入输出方向>、>>、|Shell 先解释它们

  1. 先敲 whoami、pwd、hostname，确认当前身份和位置。
  2. 敲 ls --help | head，观察帮助信息的结构。
  3. 敲 man ls，用 /human 搜索，按 q 退出。
  4. 故意敲一个不存在的命令，观察报错。
  5. 用 which ls、echo $PATH 理解命令是怎么被找到的。

代码/配置参考

hostname

小白避坑

  • 复制命令时把提示符 $ 或 # 一起复制进去，导致报错。
  • 选项和参数之间漏空格，如 ls-l，Shell 会把它当成一个整体。
  • Linux 区分大小写：LS 和 ls 不是一回事。
  • 把 Windows 的反斜杠 \ 当路径分隔符，Linux 用 /。
记忆口诀“命令是动作，选项是方式，参数是对象；不会就 --help，详细看 man。”

2-03

ls 命令入门

一句话核心ls 用来列目录内容；ls -l 看详情，ls -a 看隐藏文件，ls -lh 把大小变人类可读，三个组合 ls -alh 最常用。

本节要解决的问题

ls 是你进 Linux 后敲得最多的命令。先会“看有什么”，再会“看详情”，最后能读懂 ls -l 的每一列。

核心概念（小白也能懂）

ls
list 的缩写，列出目录中的文件和子目录；不跟参数时列当前目录。
隐藏文件
以 . 开头的文件/目录，ls 默认不显示，要用 ls -a。
. 和 ..
. 代表当前目录，.. 代表上级目录，每个目录里都有这两个特殊入口。
长格式
ls -l 输出权限、链接数、属主、属组、大小、修改时间、文件名七列。

拆开讲

ls 只列名字，适合快速看；ls -l（很多系统别名 ll）列详情；ls -a 把隐藏文件也显示出来；ls -h 把字节数变成 K/M/G，通常和 -l 一起用。

ls -l 第一列如 -rw-r--r--：第一位 - 是普通文件，d 是目录，l 是软链接；后面 9 位分三组，分别是属主、属组、其他人的 r/w/x 权限。第三、四列是属主和属组，第五列是大小，第六到八列是修改时间，最后是文件名。

ls -a 会看到 .、.. 以及 .bashrc、.ssh 等隐藏文件。隐藏文件不是“加密文件”，只是名字以点开头，常用于存放配置。

ls -R 递归列出子目录；ls -t 按修改时间从新到旧；ls -S 按大小从大到小；ls -r 反向排序。组合使用能快速定位“最近改了什么”“哪个文件最大”。

命令/操作速查

ls 常用选项

命令作用典型场景
ls列当前目录快速看有什么
ls /etc列指定目录看配置目录
ls -l长格式详情看权限、属主、大小、时间
ls -a包含隐藏文件看 .bashrc、.ssh
ls -lh详情 + 人类可读大小看日志/安装包大小
ls -alh以上组合最常用的“全都要”
ls -R递归列出子目录看整个项目结构
ls -lt按时间倒序找最近修改的文件
ls -lS按大小倒序找占空间的大文件
ls -ld /etc只看目录本身看目录权限，而不是目录内容

动手做

  1. 执行 ls、ls -l、ls -a、ls -lh，对比输出差异。
  2. 执行 ls -alh /etc | head -20，观察隐藏文件和权限列。
  3. 执行 ls -lt /var/log | head，找最近修改的日志。
  4. 执行 ls -ld /etc，对比 ls -l /etc，理解“目录本身”和“目录内容”。

代码/配置参考

ls
ls -l
ls -a
ls -lh
ls -alh /etc | head -20
ls -lt /var/log | head
ls -ld /etc

小白避坑

  • ls -a 看到 . 和 .. 以为是病毒：它们是每个目录都有的特殊目录项。
  • ls -l 只显示目录本身的信息，不显示目录里面文件的大小；要看里面用 ls -lh 目录。
  • -h 单独用通常没效果，它需要配合 -l 才有“人类可读大小”。
  • 把 ls -l 的输出当成“文件内容”：它只是元数据，不是文件里的文字。
记忆口诀“-l 看详情，-a 看隐藏，-h 好读大小，-t 看最近，-S 看最大。”

2-04

ls 命令的参数和选项

一句话核心选项决定“怎么看”，参数决定“看谁”；选项可以合并、可以放前面或后面，参数通常是目录或文件。

本节要解决的问题

这一节把“选项”和“参数”彻底分清。很多命令报错不是命令不会，而是把选项和参数放错了位置，或者把通配符用错了。

核心概念（小白也能懂）

选项顺序
多数命令的选项可以放在参数前，也可以放在参数后，如 ls -l /etc 和 ls /etc -l 通常都对。
合并选项
ls -a -l -h 可以写成 ls -alh，解析器会逐个识别。
多个参数
ls /etc /var /home 可以一次列多个目录。
通配符
* 匹配任意多个字符，? 匹配一个字符，[] 匹配范围内一个字符。由 Shell 先展开。

拆开讲

ls -l /etc 和 ls /etc -l 结果通常一样，因为 GNU 命令允许选项和参数混排。但有些老命令要求选项在前，写脚本时建议统一“命令 选项 参数”的顺序，可读性最好。

多个参数：ls -l /etc /var 会先列 /etc 再列 /var，并分别加标题。参数是“对谁做”，所以可以一次给多个对象。

通配符是 Shell 的功能，不是 ls 的功能。ls *.conf 会先被 Shell 展开成当前目录下所有 .conf 文件名，再传给 ls。如果没有匹配，默认会把 *.conf 原样传给 ls，报“No such file or directory”（除非开了 nullglob）。

-- 是“选项结束符”：如果文件名刚好以 - 开头，可以用 ls -- -file 避免被当成选项。这个技巧在处理奇怪文件名时很有用。

命令/操作速查

选项与参数的组合示例

命令解释
ls -l /etc长格式看 /etc
ls /etc -l选项后置，通常也可以
ls -alh /etc /var一次看两个目录
ls -l *.confShell 先展开当前目录的 .conf 文件
ls -l ?.txt匹配单个字符 + .txt
ls -l [abc].txt匹配 a.txt/b.txt/c.txt
ls -- -file文件名以 - 开头时，用 -- 结束选项

动手做

  1. 在 /tmp 下创建几个测试文件：touch a.txt b.txt c.log。
  2. 执行 ls -l /tmp/*.txt 和 ls -l /tmp/?.txt，观察通配符差异。
  3. 执行 ls -l /etc /var | head，观察多参数输出。
  4. 执行 ls -l /tmp/nothing*，看没有匹配时的报错。

代码/配置参考

cd /tmp
touch a.txt b.txt c.log
ls -l *.txt
ls -l ?.txt
ls -l /etc /var | head
ls -l nothing*

小白避坑

  • 通配符没匹配到文件时，Shell 可能把 * 原样传给命令，导致“找不到文件”的假象。
  • 文件名有空格却没加引号：ls my file.txt 会被当成两个参数。
  • 把 - 开头的文件名直接传给命令，被误认为选项；用 ./-file 或 --。
  • 在脚本里依赖“选项可以后置”，换到 BusyBox 等精简环境可能不兼容。
记忆口诀“选项管怎么看，参数管看谁；通配符先展开，空格文件要加引号。”

2-05

cd、pwd 命令

一句话核心pwd 告诉你“现在在哪”，cd 带你“去别处”；cd .. 回上级，cd ~ 回家，cd - 回上一次目录。

本节要解决的问题

在 Linux 里迷路很正常。记住两个命令：pwd 看位置，cd 换位置。先把“移动”练熟，后面的相对路径才不会绕晕。

核心概念（小白也能懂）

pwd
print working directory，打印当前工作目录的绝对路径。
cd
change directory，切换当前工作目录；cd 是 Shell 内置命令。
家目录
普通用户是 /home/用户名，root 是 /root；~ 代表当前用户的家目录。
上一次目录
cd - 回到上一次所在目录，并在终端打印路径。

拆开讲

pwd 输出的一定是绝对路径，例如 /home/tom/project。提示符里可能只显示 ~ 或当前目录名，想看完整路径就敲 pwd。

cd /etc 是绝对路径切换；cd project 是相对路径，进入当前目录下的 project；cd .. 回上级；cd ../.. 回上两级；cd ~ 或直接 cd 回家；cd - 回上一次目录。

cd 不加参数等于 cd ~，回当前用户家目录。cd / 回根目录。cd 到不存在的目录会报 No such file or directory；没有权限会报 Permission denied。

提示符里的 ~ 只是显示优化，不代表真实路径。例如你在 /home/tom，提示符可能显示 ~；进入 /home/tom/project 可能显示 ~/project。用 pwd 看真实路径最稳。

命令/操作速查

cd ~当前用户家目录cd 不带参数等价

动手做

  1. 执行 pwd，确认当前位置。
  2. 执行 cd /etc，再 pwd。
  3. 执行 cd ..，再 pwd；再 cd ../..。
  4. 执行 cd ~，再 pwd；执行 cd -，观察回到哪。
  5. 执行 cd /notexist，观察报错。

小白避坑

  • cd.. 中间没空格，Shell 会找名叫 cd.. 的命令，报 command not found。
  • cd - 只记录一个“上一次目录”，连续用会在两个目录之间来回跳。
  • 普通用户 cd /root 会 Permission denied，这是权限设计，不是命令坏了。
  • 路径有空格没加引号：cd my dir 会失败，应写 cd "my dir"。
记忆口诀“pwd 看在哪，cd 去别处；一点当前，两点上级，波浪回家，减号回上次。”

2-06

相对路径、绝对路径和特殊路径符

一句话核心绝对路径从 / 开始，在哪都能用；相对路径从当前目录算，依赖你站的位置；.、..、~ 是三个最常用的特殊路径符。

本节要解决的问题

同样是 cd project，在 /home/tom 下和在 /etc 下结果完全不同。搞懂相对/绝对，你才能写出“换台机器也能跑”的命令和脚本。

核心概念（小白也能懂）

绝对路径
以 / 开头，从根目录一路写到底，如 /etc/nginx/nginx.conf。位置无关，最可靠。
相对路径
不以 / 开头，从当前工作目录算起，如 conf/nginx.conf、../logs。
.
当前目录。./script.sh 表示运行当前目录下的脚本。
..
上级目录。../.. 是上两级；根目录的 .. 还是根目录。
~
当前用户家目录；~tom 表示 tom 的家目录。

拆开讲

判断方法很简单：看第一个字符是不是 /。是，就是绝对路径；不是，就是相对路径。绝对路径像“完整快递地址”，相对路径像“从我现在的位置往前走两个路口”。

cd /var/log 是绝对；cd log 是相对（当前目录下要有 log）；cd ../log 是相对（先去上级，再进 log）。脚本里推荐用绝对路径，避免被“在哪个目录执行”影响。

. 和 .. 也是目录：ls . 列当前目录，ls .. 列上级目录；cp ./a.txt /tmp 明确表示当前目录的 a.txt。执行当前目录的脚本要写 ./script.sh，因为当前目录通常不在 PATH 里。

~ 由 Shell 展开成家目录。echo ~ 看结果；cd ~/project 进家目录下的 project。注意 ~ 只在 Shell 里展开，写在配置文件里不一定被识别。

命令/操作速查

路径写法对照

写法类型含义例子
/etc/hosts绝对根下的 etc/hosts在哪执行都一样
etc/hosts相对当前目录下的 etc/hosts换目录就变
./run.sh相对当前目录的 run.sh执行脚本常用
../logs相对上级目录的 logs从子目录回退
~特殊当前用户家目录cd ~
~tom特殊tom 的家目录ls ~tom
/绝对根目录cd /

动手做

  1. 在 /tmp 下创建 pathtest/sub，进入 sub。
  2. 用 pwd 看位置，执行 ls ..、ls ../..。
  3. 执行 cd /tmp/pathtest（绝对）和 cd sub（相对），对比。
  4. 执行 echo ~、echo ~root，看 Shell 展开结果。
  5. 在 /tmp/pathtest 下写一个 hi.sh，用 ./hi.sh 执行。

代码/配置参考

mkdir -p /tmp/pathtest/sub
cd /tmp/pathtest/sub
pwd
ls ..
ls ../..
cd /tmp/pathtest     # 绝对
cd sub               # 相对
echo ~
echo ~root

小白避坑

  • 相对路径依赖当前目录：在 /home/tom 能跑的 cd project，到 /etc 就找不到。
  • 执行当前目录脚本忘记 ./，报 command not found（当前目录不在 PATH）。
  • ~ 被引号包住时可能不展开：cd "~" 会找名字叫 ~ 的目录。
  • 路径拼错大小写：Linux 区分大小写，/etc/Hosts 和 /etc/hosts 不同。
记忆口诀“斜杠开头是绝对，走到哪都认；不加斜杠是相对，先看你站哪。”

3 分钟自测

Q1/var/log 和 var/log 有什么区别？
答：前者是绝对路径；后者是相对路径，依赖当前目录。
Q2./script.sh 中的 ./ 有什么用？
答：表示当前目录，确保 Shell 执行当前目录下的脚本，而不是去 PATH 里找。
Q3~ 和 ~root 分别是什么？
答：当前用户家目录；root 用户的家目录（通常是 /root）。

mkdir 命令

一句话核心mkdir 创建目录；mkdir -p a/b/c 可以一次性创建多级目录，父目录不存在也不报错。

本节要解决的问题

装软件、做实验经常要建目录。只会 mkdir 一个目录 不够，-p 才是日常主力。

核心概念（小白也能懂）

mkdir
make directory，创建目录。
-p
parents，递归创建父目录；目录已存在也不报错。
-m
创建时直接指定权限，如 -m 755。
-v
显示创建过程，排查脚本时有用。

拆开讲

mkdir test 在当前目录建 test。如果父目录不存在，mkdir a/b 会报 No such file or directory；加 -p 就会先建 a 再建 b。

mkdir -p /opt/app/{conf,logs,data} 可以用花括号扩展一次建三个子目录（bash 特性）。写成脚本时很常用。

mkdir -p 对已存在的目录不报错，所以适合放在脚本里反复执行，这叫“幂等”。mkdir 不加 -p 对已存在目录会报 File exists。

mkdir -m 700 secret 创建时就把权限设为 700；不加 -m 则受 umask 影响，默认通常是 755。

命令/操作速查

mkdir 常用写法

命令作用注意
mkdir test建一个目录父目录必须存在
mkdir -p a/b/c递归建多级已存在也不报错
mkdir dir1 dir2一次建多个空格分隔
mkdir -m 700 secret指定权限700=只有属主可读写进入
mkdir -pv /opt/app/{conf,logs}建多个 + 显示过程花括号由 bash 展开

动手做

  1. 在 /tmp 下执行 mkdir demo，再 ls -ld demo。
  2. 执行 mkdir demo/a/b，观察报错。
  3. 执行 mkdir -p demo/a/b，再 ls -R demo。
  4. 执行 mkdir -m 700 demo/secret，ls -ld demo/secret。
  5. 执行 mkdir -p /tmp/app/{conf,logs,data}，查看结果。

代码/配置参考

cd /tmp
mkdir demo
mkdir demo/a/b          # 会报错：父目录不存在
mkdir -p demo/a/b       # 正确
mkdir -m 700 demo/secret
mkdir -p /tmp/app/{conf,logs,data}
ls -R /tmp/app

小白避坑

  • 忘记 -p，建多级目录时报 No such file or directory。
  • 目录名有空格没加引号：mkdir my dir 会建两个目录。
  • 在系统目录乱建目录：/etc、/usr 下不要随便加东西。
  • 以为 -p 会覆盖已有目录：它只是“存在就跳过”，不会清空。
记忆口诀“建多级，加 -p；建多个，空格隔；要权限，-m 跟上。”

3 分钟自测

Q1怎么一次性创建 /opt/app/conf、/opt/app/logs、/opt/app/data？
答：mkdir -p /opt/app/{conf,logs,data}。
Q2mkdir -p 对已存在的目录会怎样？
答：不报错，直接跳过（幂等）。
Q3创建目录时就想设为 700 权限，怎么写？
答：mkdir -m 700 目录名。

touch、cat、more 命令

一句话核心touch 建空文件或更新时间戳，cat 一次性看小文件，more 分页看大文件。

本节要解决的问题

这三个命令是“文件三件套”：建文件、看内容、慢慢看。先会看小文件，再学会看大文件，避免一屏刷过去什么都没看清。

核心概念（小白也能懂）

touch
文件不存在时创建空文件；存在时更新访问/修改时间，不改变内容。
cat
concatenate，把文件内容全部输出到终端，也常用来合并文件。
more
分页查看文件，空格翻页，Enter 下滚一行，q 退出。
时间戳
文件的 atime（访问）、mtime（内容修改）、ctime（元数据变更）。

拆开讲

touch a.txt 创建空文件；touch a.txt b.txt 一次建多个；touch -t 202401011200 a.txt 指定时间；touch -d "2024-01-01 12:00" a.txt 更直观。

cat file 把整个文件打印出来，适合几十行以内的小文件。cat -n file 显示行号，cat a.txt b.txt > c.txt 合并文件，cat > file 可以从键盘输入内容（Ctrl+D 结束）。

more file 分页显示，空格下一页，Enter 下一行，q 退出，/关键字 搜索。less 比 more 更强（可上下翻、搜索），服务器上更常用；但课程先讲 more，先掌握分页思想。

cat 看二进制文件会把终端搞乱（出现乱码、提示符异常），此时敲 reset 恢复。大日志文件不要用 cat，用 tail、less 或 grep。

命令/操作速查

三个命令怎么选

命令适合不适合常用选项
touch建空文件/改时间写内容-t、-d
cat小文件、合并、重定向输入大文件、二进制-n、-A
more分页浏览大文件来回翻看、搜索体验一般空格/Enter/q
less（扩展）大文件、日志—/搜索、G/g、q

动手做

  1. 执行 touch /tmp/note.txt，ls -l 看大小 0。
  2. 执行 echo "hello linux" > /tmp/note.txt 写入内容。
  3. 执行 cat /tmp/note.txt、cat -n /tmp/note.txt。
  4. 执行 cat /etc/services | more，练习空格、Enter、q。
  5. 执行 cat /tmp/note.txt /etc/hostname > /tmp/merge.txt，cat /tmp/merge.txt 看合并结果。

代码/配置参考

touch /tmp/note.txt
echo "hello linux" > /tmp/note.txt
cat /tmp/note.txt
cat -n /tmp/note.txt
cat /etc/services | more
cat /tmp/note.txt /etc/hostname > /tmp/merge.txt
cat /tmp/merge.txt

小白避坑

  • touch 不会清空已有文件，它只改时间；要清空用 > file。
  • cat 大文件刷屏，找不到重点；大文件用 less 或 tail。
  • more 里按 Ctrl+C 可能直接退出，想退出按 q。
  • cat > file 会覆盖原内容，想追加用 cat >> file。
记忆口诀“touch 建空文件，cat 一口吞，more 分页看；大文件别用 cat。”

3 分钟自测

Q1touch 一个已存在的文件会发生什么？
答：更新它的访问/修改时间，内容不变。
Q2怎么给文件内容加行号显示？
答：cat -n 文件名。
Q3more 里怎么退出？
答：按 q。

cp、mv、rm 命令

一句话核心cp 复制（目录要 -r），mv 移动或重命名，rm 删除（不进回收站，-rf 极高危）。

本节要解决的问题

这是最容易“一失手成千古恨”的一节。cp/mv/rm 本身不难，难的是路径和通配符。练的时候先在 /tmp 下建测试目录，别拿 /etc 练手。

核心概念（小白也能懂）

cp
copy，复制文件或目录；复制目录必须加 -r（递归）。
mv
move，移动文件/目录；在同一目录内就是重命名。
rm
remove，删除文件；删除目录用 -r，强制不提示用 -f。
覆盖
目标已存在时，cp/mv 默认可能直接覆盖；用 -i 可以交互确认。

拆开讲

cp a.txt b.txt 复制文件；cp a.txt /tmp/ 复制到目录；cp -r dir1 dir2 复制目录；cp -a dir1 dir2 保留权限、时间、链接等属性，适合备份。

mv a.txt b.txt 如果 b.txt 不存在就是重命名；存在就是覆盖（默认）。mv a.txt /tmp/ 是移动。mv dir1 dir2 如果 dir2 存在，会把 dir1 放到 dir2 里面；如果不存在，就是重命名。

rm a.txt 删除文件；rm -r dir 递归删除目录；rm -rf dir 强制递归、不提示。Linux 没有回收站，删了基本找不回。执行前先 pwd、ls，确认路径。

批量删除尤其危险：rm -rf /tmp/test* 中如果 * 没匹配好，或者路径多了一个空格，可能删到别的东西。生产环境常见做法是先 ls 同样的通配符确认，再删。

命令/操作速查

cp/mv/rm 常用写法

命令作用注意
cp a.txt b.txt复制文件目标存在会覆盖
cp -r dir1 dir2复制目录不加 -r 报错
cp -a dir1 dir2归档复制保留权限/时间/链接
mv a.txt b.txt重命名同目录内
mv a.txt /tmp/移动目标目录要存在
rm a.txt删文件不进回收站
rm -r dir删目录会逐个提示（视 alias）
rm -rf dir强制删目录高危，先确认路径

动手做

  1. 在 /tmp 下建 safedemo，进入后创建 a.txt、b.txt 和 sub 目录。
  2. 执行 cp a.txt a.bak、cp -r sub sub2，ls -R 看结果。
  3. 执行 mv a.bak renamed.txt，再 mv renamed.txt sub/。
  4. 执行 rm b.txt、rm -r sub2，确认删除。
  5. 练习“先 ls 再 rm”：ls /tmp/safedemo/*.txt，确认后再 rm -rf /tmp/safedemo/*.txt。

代码/配置参考

mkdir -p /tmp/safedemo/sub
cd /tmp/safedemo
touch a.txt b.txt
cp a.txt a.bak
cp -r sub sub2
mv a.bak renamed.txt
mv renamed.txt sub/
rm b.txt
rm -r sub2
ls -R /tmp/safedemo

小白避坑

  • cp 复制目录忘记 -r，报 omitting directory。
  • mv 目标目录已存在时，把源“放进去”而不是改名，结果路径多一层。
  • rm -rf 后面多打一个空格或斜杠，可能删到根目录/系统目录；永远先确认路径。
  • 用 root 执行 rm，系统文件也能被删；日常尽量用普通用户 + sudo。
  • 以为删除文件要看文件自己的写权限：其实能否删除取决于父目录的写权限。
记忆口诀“复制目录加 -r，移动同盘即改名；删除没有回收站，rm -rf 先看清。”

3 分钟自测

Q1复制一个目录为什么要加 -r？
答：目录需要递归复制里面的所有内容，cp 默认不递归。
Q2mv dir1 dir2 中 dir2 已存在时会发生什么？
答：dir1 会被移动到 dir2 里面，变成 dir2/dir1。
Q3为什么 rm -rf 很危险？
答：递归强制删除、不提示、不进回收站，路径写错可能删掉系统或重要数据。

which、find 命令

一句话核心which 找“命令在哪”，find 按名字、类型、大小、时间在目录树里找“文件在哪”。

本节要解决的问题

文件多了，靠 ls 一层层翻太慢。which 解决“命令从哪来”，find 解决“文件藏哪了”。这两个是排错和运维的高频工具。

核心概念（小白也能懂）

which
在 PATH 中查找命令对应的可执行文件路径。
find
从指定目录开始递归遍历，按条件查找文件/目录，功能非常强。
表达式
find 的条件组合，如 -name、-type、-size、-mtime，可用 -a/-o/! 组合。
-exec
对找到的每个文件执行命令，{} 代表文件名，\; 表示命令结束。

拆开讲

which ls 输出 /usr/bin/ls；which python 可能找不到，因为没装或不在 PATH。whereis 还能找源码/手册，type 能区分别名/内置命令。

find /etc -name "*.conf" 在 /etc 下按名字找；find . -type f 只找普通文件；find /var/log -type f -size +10M 找大于 10M 的日志；find /tmp -mtime -1 找一天内修改过的。

find 默认递归整棵树，从 / 开始会扫全盘，慢且容易刷权限错误。加 2>/dev/null 屏蔽错误；加 -maxdepth 2 限制深度；先缩小目录范围。

find . -name "*.log" -exec rm -f {} \; 可以对找到的文件执行命令；更安全的做法是先 -print 确认，再执行删除。-delete 也能删，但同样要先确认。

命令/操作速查

find 常用条件

写法作用例子
-name "*.conf"按名字（区分大小写）find /etc -name "*.conf"
-iname "*.conf"按名字（忽略大小写）find . -iname "*.CONF"
-type f / d / l普通文件/目录/软链接find . -type d
-size +10M大于 10Mfind /var -size +100M
-mtime -77 天内修改过find /tmp -mtime -7
-user tom属主是 tomfind /home -user tom
-maxdepth 2最多向下 2 层find /etc -maxdepth 2 -name "*.conf"
-exec ... \;对结果执行命令find . -name "*.tmp" -exec rm {} \;

动手做

  1. 执行 which ls、which cd（cd 是内置命令，可能找不到）、type ls。
  2. 执行 find /etc -maxdepth 2 -name "*.conf" 2>/dev/null | head。
  3. 执行 find /var/log -type f -size +1M 2>/dev/null | head。
  4. 在 /tmp/finddemo 建几个文件，用 find 按名字/类型/时间查找。
  5. 用 -exec 前先 -print 确认结果，再执行操作。

代码/配置参考

which ls
type cd
find /etc -maxdepth 2 -name "*.conf" 2>/dev/null | head
find /var/log -type f -size +1M 2>/dev/null | head
mkdir -p /tmp/finddemo && touch /tmp/finddemo/{a.log,b.txt,c.log}
find /tmp/finddemo -name "*.log"
find /tmp/finddemo -type f -name "*.log" -print

小白避坑

  • find / -name ... 扫全盘，慢且大量 Permission denied；先缩小目录。
  • 通配符没加引号，Shell 先展开，find 收到的条件就变了；建议 -name "*.log"。
  • -mtime -7 是“7 天内”，+7 是“7 天以前”，正负号别记反。
  • -exec 直接接 rm 很危险，先 -print 看清单。
  • which 找不到不代表没装，可能只是不在 PATH；用 find / -name 命令名 或绝对路径确认。
记忆口诀“which 找命令，find 找文件；名字加引号，根目录别乱扫。”

3 分钟自测

Q1which 和 find 的查找对象有什么不同？
答：which 在 PATH 里找可执行命令；find 在目录树里按条件找文件/目录。
Q2怎么在 /etc 下找所有 .conf 文件，且最多向下 2 层？
答：find /etc -maxdepth 2 -name "*.conf"。
Q3find . -mtime -7 是什么意思？
答：找当前目录下 7 天内修改过的文件。

grep、wc 命令和管道符

一句话核心grep 在文件内容里找关键字，wc 统计行数/单词数/字节数，管道 | 把前一个命令的输出变成后一个命令的输入。

本节要解决的问题

单个命令能力有限，组合起来才强大。ps -ef | grep java、cat app.log | grep error | wc -l 这类组合，是日常排错的基本功。

核心概念（小白也能懂）

grep
Global Regular Expression Print，按行匹配字符串/正则，输出匹配行。
wc
word count，统计行数 -l、单词数 -w、字节数 -c。
管道 |
把左边命令的标准输出接到右边命令的标准输入；左边必须是“会输出”的命令。
正则
一种描述文本模式的语言；grep 默认用基础正则，-E 用扩展正则。

拆开讲

grep "error" app.log 找包含 error 的行；-i 忽略大小写；-v 反向（不含关键字的行）；-n 显示行号；-c 只输出匹配行数；-r 递归目录。

wc -l file 统计行数，wc -w 单词数，wc -c 字节数；不加选项输出三列（行、词、字节）。统计“有多少条错误”常用 grep -c error app.log 或 grep error app.log | wc -l。

管道把多个小工具串起来：ps -ef | grep java 找 Java 进程；cat access.log | grep 404 | wc -l 统计 404 次数；ls -l | grep "^d" 只列目录。管道只传标准输出，错误信息默认还在终端。

grep 找的是内容，find 找的是文件名。grep -r "keyword" /etc 会递归搜索 /etc 下所有文件内容；find /etc -name "*keyword*" 找文件名含 keyword 的文件。

命令/操作速查

grep/wc/管道常用组合

命令作用
grep -n "error" app.log显示错误行和行号
grep -i "error" app.log忽略大小写
grep -v "#" config排除注释行
grep -c "error" app.log统计匹配行数
grep -r "keyword" /etc递归搜索目录内容
wc -l file统计行数
ps -ef | grep java过滤 Java 进程
cat app.log | grep error | wc -l统计错误条数
ls -l | grep "^d"只列目录行

动手做

  1. 准备测试文件：printf "apple\nbanana\nApple\nerror 404\n" > /tmp/fruit.txt。
  2. 执行 grep -n apple /tmp/fruit.txt、grep -in apple /tmp/fruit.txt。
  3. 执行 grep -v apple /tmp/fruit.txt、grep -c apple /tmp/fruit.txt。
  4. 执行 cat /tmp/fruit.txt | grep -i apple | wc -l。
  5. 执行 ps -ef | grep sshd，观察 grep 自身也可能出现在结果里。

代码/配置参考

grep -in apple /tmp/fruit.txt
grep -v apple /tmp/fruit.txt
grep -c apple /tmp/fruit.txt

小白避坑

  • ps -ef | grep java 结果里有一条 grep 自己；用 grep -v grep 或 pgrep -af java。
  • 关键字含空格/特殊符号没加引号，被 Shell 拆开或展开。
  • 把管道当成“文件参数”：grep error | app.log 是错的，应该是 grep error app.log。
  • wc -l 统计的是换行符数量；最后一行没有换行时可能少算 1。
记忆口诀“grep 找内容，find 找名字；wc 数行数，管道串流水线。”

3 分钟自测

Q1统计日志中 error 出现的行数，有哪两种写法？
答：grep -c error app.log 或 grep error app.log | wc -l。
Q2管道 | 传递的是什么？
答：左边命令的标准输出，作为右边命令的标准输入。
Q3怎么在 /etc 下递归搜索包含 nameserver 的文件？
答：grep -r "nameserver" /etc。

echo、tail 命令和重定向符

一句话核心echo 输出文字/变量，tail 看文件末尾并实时跟踪日志；> 覆盖写入，>> 追加，2> 重定向错误，2>&1 合并错误到标准输出。

本节要解决的问题

会看文件还不够，还要会“写文件”和“盯日志”。重定向是 Shell 的基础能力，理解了它，你才能写脚本、做日志分析。

核心概念（小白也能懂）

echo
把参数输出到标准输出；常用来打印变量、写文件、调试脚本。
tail
显示文件末尾若干行，-f 实时跟踪新增内容，常用来盯日志。
标准输出/错误
fd 1 是标准输出，fd 2 是标准错误；正常结果走 1，报错走 2。
重定向
改变命令的输入/输出方向：> 覆盖、>> 追加、< 输入、2> 错误。

拆开讲

echo "hello" 输出 hello；echo $HOME 输出变量；echo -e "a\nb" 让 \n 生效；echo text > file 覆盖写入，echo text >> file 追加。

tail -n 20 app.log 看最后 20 行；tail -f app.log 实时跟踪，Ctrl+C 退出；tail -F app.log 在日志轮转后还能继续跟（更稳）。

> 会先清空文件再写，误用会丢数据；>> 才追加。cmd > out.log 2>&1 把正常输出和错误都写进 out.log；cmd 2> err.log 只把错误写进 err.log。

/dev/null 是“黑洞”，cmd > /dev/null 2>&1 表示丢弃所有输出，常用于定时任务。tee 可以“既显示在屏幕又写文件”：cmd | tee out.log。

命令/操作速查

重定向符号速查

写法作用例子
> file标准输出覆盖到文件echo hi > a.txt
>> file标准输出追加到文件echo hi >> a.txt
2> file标准错误写到文件cmd 2> err.log
2>&1错误合并到标准输出cmd > all.log 2>&1
&> file输出和错误都写文件（bash）cmd &> all.log
< file从文件读输入wc -l < a.txt
> /dev/null丢弃输出cmd > /dev/null 2>&1
| tee file屏幕显示并写文件cmd | tee out.log

动手做

  1. 执行 echo "line1" > /tmp/echo.txt，再 echo "line2" >> /tmp/echo.txt。
  2. 执行 cat /tmp/echo.txt，确认是两行。
  3. 执行 echo "line3" > /tmp/echo.txt，再 cat，观察只剩 line3。
  4. 执行 tail -n 2 /tmp/echo.txt。
  5. 开两个终端，一个 tail -f /tmp/echo.txt，另一个追加内容，观察实时输出。

代码/配置参考

echo "line1" > /tmp/echo.txt
echo "line2" >> /tmp/echo.txt
cat /tmp/echo.txt
echo "line3" > /tmp/echo.txt
cat /tmp/echo.txt
tail -n 2 /tmp/echo.txt
tail -f /tmp/echo.txt
# 另一个终端：echo "new line" >> /tmp/echo.txt

小白避坑

  • > 当 >> 用，覆盖了原文件；写配置/日志前先想清楚。
  • 2>&1 顺序写反：cmd 2>&1 > file 错误仍会打到终端。
  • tail -f 跟的是文件描述符，日志被轮转后可能“跟丢”，用 -F。
  • echo $VAR 变量为空时输出空行，不知道是没定义还是值为空；用 echo "[$VAR]" 辅助判断。
记忆口诀“一个大于覆盖，两个大于追加；2 是错误，&1 是合并；tail -f 盯日志。”

3 分钟自测

Q1> 和 >> 的区别？
答：> 覆盖原文件；>> 在末尾追加。
Q2怎么把命令的正常输出和错误都写入 all.log？
答：cmd > all.log 2>&1。
Q3怎么实时查看不断增长的日志？
答：tail -f 日志文件，轮转场景用 tail -F。

vi 编辑器

一句话核心vi 有三种模式：命令模式、插入模式、末行模式；核心流程是 vi 文件 → i 插入 → Esc → :wq 保存退出。

本节要解决的问题

服务器上没有记事本，改配置几乎都用 vi/vim。很多人第一次用 vi 会“卡死”，其实只是没弄懂模式。记住三个模式，就不慌了。

核心概念（小白也能懂）

命令模式
打开文件后的默认模式，按键是命令（dd 删行、yy 复制），不能直接打字。
插入模式
按 i/a/o 等进入，可以像记事本一样输入文字；按 Esc 回到命令模式。
末行模式
命令模式下按 : 进入，执行保存、退出、替换等命令，回车执行。
vim
vi 的增强版，支持语法高亮、插件；大多数系统 vi 就是 vim 的别名/软链接。

拆开讲

打开文件：vi file。默认在命令模式，按 i 在光标前插入，a 在后插入，o 在下一行新开一行，O 在上一行新开，I 行首，A 行尾。输入完按 Esc 回命令模式。

保存退出：:w 保存，:q 退出，:wq 保存并退出，:q! 不保存强制退出，:x 保存退出（有修改才写），ZZ 命令模式下保存退出。

移动：h j k l 左下上右；gg 文件头，G 文件尾，0 行首，$ 行尾，w 下一个词，b 上一个词，Ctrl+f/b 翻页，:n 跳到第 n 行。

编辑：x 删字符，dd 删整行，yy 复制整行，p 粘贴，u 撤销，Ctrl+r 重做，dw 删一个词，cw 改一个词，r 替换一个字符，J 合并下一行。

搜索替换：/keyword 搜索，n 下一个，N 上一个；:%s/old/new/g 全文替换，:%s/old/new/gc 替换前确认。可视模式 v 选字符、V 选行、Ctrl+v 选块。

命令/操作速查

vi 必背操作

场景按键说明
进入插入i / a / o光标前/后/下一行
回到命令Esc最常按的键
保存退出:wq 或 ZZ写入并离开
不保存退出:q!放弃修改
只保存:w继续编辑
删一行dd可配合数字 3dd
复制/粘贴yy / p3yy 复制 3 行
撤销/重做u / Ctrl+r改错了先撤销

动手做

  1. 执行 vi /tmp/vi-demo.txt，按 i，输入三行文字。
  2. 按 Esc，输入 :wq 回车，回到 Shell。
  3. 再次打开，按 gg、G、dd、u，练习移动/删除/撤销。
  4. 输入 :set nu 显示行号，/关键字 搜索。
  5. 故意修改但不保存，输入 :q! 退出，确认文件没变。

代码/配置参考

# 按 i 输入：
# hello linux
# this is vi practice
# 按 Esc，输入 :wq 回车

cat /tmp/vi-demo.txt

# 命令模式：gg、G、dd、u
# 末行模式：:set nu、/hello、:%s/hello/hi/g、:wq

小白避坑

  • 打开 vi 直接打字，结果触发各种命令；先按 i 进插入模式。
  • 改完直接关窗口，没保存；用 :wq 或 ZZ。
  • Ctrl+C 不是 vi 的退出方式；它会中断当前操作，退出用 Esc + :q!。
  • 在只读文件/无权限文件上 :wq 失败；检查权限或用 sudo。
  • 服务器上 vi 不支持方向键/语法高亮，装 vim 或改配置；基础操作仍然通用。
记忆口诀“i 插入，Esc 回；冒号进末行，wq 保存退；q! 不后悔。”

Q2修改文件后不想保存，怎么退出？
答：Esc 后输入 :q!。
Q3怎么在 vi 里全文把 old 替换成 new？
答：: %s/old/new/g（冒号后不要有空格）。

通关自测

Q1ls -lh 中 -l 和 -h 分别做什么？
答：-l 长格式显示详情；-h 把大小显示为 K/M/G 等人类可读单位（通常配合 -l）。
Q2cd .. 和 cd - 有什么区别？
答：cd .. 回上级目录；cd - 回上一次所在目录。
Q3cp -r /etc /tmp/etc_bak 和 cp /etc /tmp/etc_bak 有什么区别？
答：前者递归复制整个目录；后者不加 -r 会报“omitting directory”之类的错误。
Q4rm -rf 为什么危险？
答：递归且强制，不提示、不进回收站，删错目录可能直接毁系统。
Q5cmd > file 2>&1 和 cmd 2>&1 > file 有什么区别？
答：前者标准输出和错误都进 file；后者先把错误指向终端，再把标准输出重定向到 file，错误仍显示在终端。
Q6vi 中如何不保存强制退出？
答：按 Esc，输入 :q! 回车。
