3-01

Linux 的 root 用户

一句话核心root 是 UID 为 0 的超级管理员，权限不受普通权限位限制；日常应少用 root，用 su - 切换或用 sudo 借权。

本节要解决的问题

Linux 里“权限不够”时，很多人第一反应就是 sudo 或切 root。但 root 能做的事越多，误操作代价越大。先理解 root 是什么，再学会安全地用它。

核心概念（小白也能懂）

root
超级管理员账号，UID=0，GID=0；可以读写任何文件、终止任何进程、改任何配置。
UID
用户 ID，系统内部用数字识别用户；root 固定为 0，普通用户通常从 1000 开始。
su
switch user，切换用户；su - 加载目标用户的登录环境。
sudo
以其他用户（默认 root）身份执行一条命令，权限由 /etc/sudoers 配置。
最小权限原则
只给完成工作所需的最小权限，降低误操作和安全风险。

拆开讲

普通用户执行 whoami 显示自己的名字，id 显示 UID/GID 和所属组。root 的 id 输出 uid=0(root) gid=0(root)。提示符 # 通常表示 root，$ 表示普通用户，但提示符可以改，不能只靠它判断身份。

su - 会切换到 root，并加载 root 的登录环境（PATH、HOME、别名等），工作目录变成 /root；su 不加 - 只切身份，环境变量可能还是原用户的，容易出现“命令找不到”的怪问题。退出用 exit 或 Ctrl+D。

sudo 命令 用当前用户密码验证，然后以 root 执行这一条命令；sudo -i 相当于登录式 root shell。能否 sudo 取决于 /etc/sudoers，CentOS 里常在 wheel 组的配置行。改 sudoers 一定用 visudo，它会做语法检查，避免改坏后所有人无法 sudo。

root 不是“必须一直用”的账号。正确姿势：日常用普通用户登录，需要改系统配置时 sudo vim /etc/...；需要连续做多步管理操作时再 su -，做完 exit。这样能减少“手滑删库”的概率。

命令/操作速查

su 与 sudo 怎么选

场景推荐原因
改一个系统配置sudo vim /etc/xxx只提权一条命令，风险小
连续做多项管理su -进入 root 环境，效率高
脚本里提权sudo 命令可控、可审计
切到普通用户测试su - tom加载 tom 的环境
忘记加 - 导致 PATH 不对su -登录环境完整

动手做

  1. 用普通用户执行 id、whoami，确认身份。
  2. 执行 su -，输入 root 密码，再 id、pwd、echo $HOME。
  3. 执行 exit 回到普通用户。
  4. 执行 sudo id，输入自己的密码，观察输出。
  5. 用 sudo -l 查看当前用户被允许执行哪些命令（可能需要密码）。

小白避坑

  • su 不加 -，PATH 还是原用户的，导致 useradd 等命令找不到；管理操作建议 su -。
  • 把 root 密码告诉所有人，或允许 root 直接 SSH 登录，安全风险极高。
  • 在 root 下执行 rm -rf，没有权限拦着你，删错就是灾难。
  • 改 /etc/sudoers 不用 visudo，语法错误可能导致 sudo 完全不可用。
  • 以为 sudo 的密码是 root 密码：默认是当前用户自己的密码。
记忆口诀“root 是 0 号，权限无上限；日常用 sudo，连续用 su -。”

3-02

用户和用户组

一句话核心用户是登录身份，用户组是权限的集合；用 useradd/groupadd 建，用 usermod -aG 加组，用 id/groups 查关系。

本节要解决的问题

公司里每个同事一个账号，开发/运维/测试各是一个组。给组授权，比给每个人逐个授权省事得多。这一节把“账号”和“组”的关系理清。

核心概念（小白也能懂）

用户
登录系统的主体，有用户名、UID、家目录、登录 Shell、密码。
用户组
一组用户的集合，用来批量授权；每个用户有一个主组，还可以有多个附加组。
主组 vs 附加组
新建文件默认属于主组；附加组用于额外权限，如把 tom 加入 dev 组。
系统用户
为服务运行而建的用户（如 nginx、mysql），通常不能登录，UID 较小。
家目录
用户登录后的默认目录，普通用户在 /home/用户名，root 在 /root。

拆开讲

/etc/passwd 每行一个用户：用户名:x:UID:GID:描述:家目录:登录Shell。密码不在这里，实际哈希在 /etc/shadow（只有 root 能读）。/etc/group 记录组名、GID 和成员。

建用户：useradd -m -s /bin/bash -G dev tom，-m 建家目录，-s 指定 Shell，-G 指定附加组。然后 passwd tom 设密码。useradd 不加 -m 时是否建家目录取决于 /etc/login.defs 的 CREATE_HOME，初学建议显式加 -m。

改组：groupadd dev 建组；usermod -aG dev tom 把 tom 追加到 dev 组；gpasswd -a tom dev 也可以。usermod -G dev tom 会覆盖 tom 原有的附加组，一定要加 -a。

查关系：id tom 看 UID/GID/组；groups tom 看所属组；getent passwd tom 查账号数据库。删用户：userdel tom 只删账号，userdel -r tom 连家目录和邮件一起删。

服务用户（nginx、mysql）通常 Shell 是 /sbin/nologin，不能登录，只能运行服务。这是安全设计，不要为了方便把它改成 /bin/bash。

命令/操作速查

用户/组管理命令

命令作用例子

passwd tom设置/修改密码root 可改任意用户
usermod -aG dev tom追加附加组a 不能少
userdel -r tom删用户+家目录慎用 -r
groupadd dev建组—
gpasswd -a tom dev加组成员等同于 usermod -aG
gpasswd -d tom dev移出组—
id tom查 UID/GID/组排查权限
groups tom查所属组简单直观
getent passwd tom查账号数据库比直接 cat 更规范

动手做

  1. 用 root 执行 groupadd dev，再 useradd -m -s /bin/bash -G dev tom。
  2. 执行 passwd tom，设置密码。
  3. 执行 id tom、groups tom，确认组关系。
  4. 执行 su - tom，pwd 看是否在 /home/tom，exit 返回。
  5. 执行 usermod -aG wheel tom（CentOS 的 wheel 组可 sudo），再 id tom 验证。
  6. 最后用 userdel -r tom 清理（练习环境再删）。

小白避坑

  • usermod -G dev tom 覆盖了原有附加组，导致用户失去其他权限；用 -aG。
  • userdel 不加 -r，家目录残留在 /home，时间久了占空间。
  • 给服务用户设置 /bin/bash，增加被登录攻击的风险。
  • 删用户前没确认是否有运行中的进程/定时任务，删完服务报错。
  • 直接手改 /etc/passwd，容易破坏格式；用 vipw 或命令。
记忆口诀“useradd 建号，passwd 设密；加组用 -aG，删号记得 -r。”

3-03

查看权限控制信息

一句话核心ls -l 的 10 位权限串：第 1 位是类型，后 9 位分属主/属组/其他人三组，每组 rwx；r=4、w=2、x=1。

本节要解决的问题

“Permission denied”是 Linux 最常见的报错之一。看懂权限串，你才能判断是“缺读”“缺写”还是“缺进入目录的 x”。

核心概念（小白也能懂）

权限串
如 -rwxr-xr--：第 1 位文件类型，后面 9 位每 3 位一组。
属主 u
文件的所有者，通常是创建者；用 chown 改。
属组 g
文件所属的用户组；组内用户按第二组权限访问。
其他人 o
既不是属主、也不在属组里的其他用户。
特殊位
setuid(4)、setgid(2)、sticky(1)，会占用 x 的位置显示为 s/S/t/T。

拆开讲

文件类型：- 普通文件，d 目录，l 软链接，c 字符设备，b 块设备，s 套接字，p 管道。初学最常看 - 和 d。

权限含义要分文件/目录：文件 r=读内容，w=改内容，x=执行（脚本/程序）；目录 r=列出目录名，w=在目录里创建/删除文件，x=进入目录/访问其中文件。目录没有 x，即使文件有 rwx 也进不去。

数字换算：r=4，w=2，x=1，三组相加。rwx=7，rw-=6，r-x=5，r--=4，-wx=3，-w-=2，--x=1，---=0。-rwxr-xr-- = 754。

stat file 能看到八进制权限（如 0644）、属主、属组、三个时间。umask 决定新建文件的默认权限：文件默认 666 减去 umask，目录默认 777 减去 umask；常见 umask 022 → 文件 644、目录 755。

特殊位：setuid 让程序以属主身份运行（如 /usr/bin/passwd 显示 rws）；setgid 让目录下新文件继承目录属组；sticky 让目录里只有文件属主/root 能删自己的文件，/tmp 通常是 drwxrwxrwt（1777）。

命令/操作速查

rwx 对文件和目录的不同含义

权限对文件对目录
r读取文件内容列出目录中的文件名（ls）
w修改文件内容在目录中创建/删除/重命名文件
x执行文件（脚本/程序）进入目录（cd）、访问目录内文件
rwx读+写+执行列+增删+进入
无 x 有 r能读不能执行能看名字但不能 cd 进去

动手做

  1. 执行 ls -l /etc/passwd /tmp /usr/bin/passwd，观察不同类型和权限。
  2. 执行 stat /etc/passwd，找到 Access: (0644/-rw-r--r--)。
  3. 执行 umask，再 touch /tmp/umask-test、mkdir /tmp/umask-dir，看默认权限。
  4. 执行 ls -ld /tmp，观察末尾的 t（sticky）。
  5. 用 namei -l /etc/passwd 看路径上每一级目录的权限（扩展）。

代码/配置参考

ls -l /etc/passwd /tmp /usr/bin/passwd
stat /etc/passwd
umask
touch /tmp/umask-test
mkdir /tmp/umask-dir
ls -ld /tmp/umask-test /tmp/umask-dir /tmp

小白避坑

  • 以为文件有 rwx 就一定能访问：还要看路径上每一级目录是否有 x。
  • 以为目录的 w 是“改目录名”：目录 w 主要影响在其中创建/删除文件。
  • 忽略属组：用户可能在属组里，实际按组权限访问，不是“其他人”。
  • 把 s/S/t/T 当普通字母：s 表示同时有 x，S 表示没有 x；t 同理。
  • umask 是“掩码”，不是直接权限；新文件权限 = 默认权限 & ~umask。
记忆口诀“类型一位，权限九位；属主属组其他人，r4 w2 x1；目录没 x 进不去。”

3-04

chmod 命令

一句话核心chmod 改权限：符号法 u/g/o/a +/-/= rwx，数字法 chmod 755；目录递归用 -R，但别乱用。

本节要解决的问题

脚本不能执行、网页打不开、目录进不去，很多时候一个 chmod 就解决。但 chmod 也是“安全放大器”，给错权限比不给更危险。

核心概念（小白也能懂）

chmod
change mode，修改文件/目录的权限位。
符号法
用 u/g/o/a 指定对象，+/-/= 指定动作，rwx 指定权限，如 u+x。
数字法
用三位八进制数表示 u/g/o，如 755、644、600。
-R
递归修改目录及其所有内容；范围大，慎用。

拆开讲

符号法：chmod u+x script.sh 给属主加执行；chmod go-w file 去掉属组和其他人的写；chmod a=r file 所有人只读；chmod u=rwx,g=rx,o= file 一次设三组。

数字法：chmod 755 dir = rwxr-xr-x；chmod 644 file = rw-r--r--；chmod 600 key.pem = rw-------；chmod 777 = 所有人全权限（危险）。

常用场景：脚本 chmod +x deploy.sh；SSH 私钥 chmod 600 ~/.ssh/id_rsa（权限太大 SSH 会拒绝）；网页目录 chmod -R 755 /var/www/html；配置文件 chmod 644。

-R 递归会把目录里所有文件都改掉，可能把不该执行的配置文件变成可执行。对目录递归前先 ls -R 或 find 看清范围；目录和文件通常需要不同权限（目录 755、文件 644）。

命令/操作速查

chmod 常见写法

命令结果场景
chmod u+x run.sh属主可执行脚本
chmod 755 dirrwxr-xr-x目录/可执行程序
chmod 644 filerw-r--r--普通配置文件
chmod 600 id_rsarw-------SSH 私钥
chmod 777 filerwxrwxrwx不推荐，除非临时测试
chmod -R 755 /var/www递归设目录和文件注意文件也会变成可执行
chmod a-x file所有人去掉执行误加执行时

动手做

  1. 在 /tmp 建 chmod-demo.sh，写入 echo hi。
  2. 执行 ls -l，再 ./chmod-demo.sh，观察 Permission denied。
  3. 执行 chmod u+x chmod-demo.sh，再 ./chmod-demo.sh。
  4. 执行 chmod 644 chmod-demo.sh，再执行，观察又没权限。
  5. 执行 chmod 755 chmod-demo.sh，验证。
  6. 创建目录和文件，练习 chmod -R 755 后 ls -lR 观察。

代码/配置参考

cd /tmp
echo 'echo hello' > chmod-demo.sh
ls -l chmod-demo.sh
./chmod-demo.sh          # Permission denied
chmod u+x chmod-demo.sh
./chmod-demo.sh          # hello
chmod 644 chmod-demo.sh
./chmod-demo.sh          # 又失败
chmod 755 chmod-demo.sh
./chmod-demo.sh

小白避坑

  • 遇到权限问题就 chmod 777：短期能通，长期是安全漏洞。
  • 对 /etc、/usr 等系统目录 chmod -R，可能导致系统命令/服务全部异常。
  • SSH 私钥权限不是 600，SSH 会报 “bad permissions” 拒绝使用。
  • 只改文件权限，忘了父目录没有 x，仍然访问不了。
  • 符号法 chmod +x 默认给所有对象加 x（受 umask 影响），精确控制用 u+x。
记忆口诀“u 属主，g 属组，o 其他人，a 全体；加加减减，数字 755 最常用。”

3 分钟自测

Q2给脚本加执行权限，最常用的两种写法？

3-05

chown 命令

一句话核心chown 改文件属主/属组：chown 用户 文件、chown 用户:组 文件、chown -R 用户:组 目录；普通用户不能把文件送给别人。

本节要解决的问题

把网站目录复制到服务器后，文件属主可能还是 root，Nginx 读不了。chown 就是解决“文件归谁”的问题。

核心概念（小白也能懂）

chown
change owner，修改文件/目录的属主和属组，通常需要 root。
chgrp
只改属组，等价于 chown :组 文件。
属主/属组
ls -l 第三、四列；决定按哪组权限位访问。
-R
递归修改目录及内部所有文件，常用于网站目录、数据目录。

拆开讲

chown tom file 把属主改成 tom；chown tom:dev file 同时改属主和属组；chown :dev file 只改属组；chown -R tom:dev /data/app 递归改整个目录。

普通用户只能改自己文件的属组（且必须是自己的组），不能把文件属主改成别人；改属主基本都要 root。这就是为什么部署网站后常用 sudo chown -R nginx:nginx /usr/share/nginx/html。

chown --reference=ref file 按参考文件复制归属；chown -h 修改软链接本身而不是目标。递归时默认会跟随符号链接的行为要留意，生产环境先确认。

chown 只改“归属”，不改“权限”。如果文件属主对了但还是 Permission denied，继续看 chmod 和父目录权限。

命令/操作速查

chown 常见写法

命令作用场景
chown tom file改属主文件归 tom
chown tom:dev file改属主和属组最常见
chown :dev file只改属组团队共享
chown -R nginx:nginx html递归改网站目录Nginx 读文件
chgrp dev file只改属组等价 chown :dev
chown --reference=a b按 a 的归属改 b批量对齐

动手做

  1. 用 root 在 /tmp 建 ownerdemo 和文件。
  2. 执行 chown tom:tom /tmp/ownerdemo，ls -ld 看变化。
  3. 执行 chown -R tom:dev /tmp/ownerdemo，ls -lR 看内部文件。
  4. 用 chgrp dev /tmp/ownerdemo/file 只改组。
  5. 用普通用户尝试 chown root file，观察被拒绝。

代码/配置参考

mkdir -p /tmp/ownerdemo
touch /tmp/ownerdemo/a.txt
chown tom:tom /tmp/ownerdemo
ls -ld /tmp/ownerdemo
chown -R tom:dev /tmp/ownerdemo
ls -lR /tmp/ownerdemo
chgrp dev /tmp/ownerdemo/a.txt
ls -l /tmp/ownerdemo/a.txt

小白避坑

  • chown -R 用在 /、/etc 等系统目录，可能让系统服务全部起不来。
  • 以为 chown 会顺便改权限：它只改归属，权限要另用 chmod。
  • 冒号写错/漏写：chown tom dev file 会被理解为“属主 tom、属组 dev、文件 file”，不是“tom 的 dev 文件”。
  • 软链接：默认 chown 可能改的是目标文件，想改链接本身用 -h。
  • 普通用户不能把文件 chown 给别人，报 Operation not permitted 是正常的。
记忆口诀“chown 改归谁，chmod 改能做啥；用户冒号组，递归加 -R。”

3 分钟自测

Q1把 /data 及其内容改成 tom 属主、dev 属组，怎么写？
答：chown -R tom:dev /data。
Q2chown 和 chmod 的区别？
答：chown 改属主/属组；chmod 改读/写/执行权限。
Q3普通用户能把文件 chown 给 root 吗？
答：不能，通常只有 root 能改变文件属主。

用户与权限
├─ 身份：root(UID 0) / 普通用户 / 系统用户；su - 切换，sudo 借权
├─ 账号：useradd / usermod / userdel / passwd；组 groupadd / gpasswd
├─ 文件：/etc/passwd、/etc/shadow、/etc/group、/etc/gshadow
├─ 权限：类型(10位) + 属主 u + 属组 g + 其他人 o；r=4 w=2 x=1
├─ 改权限：chmod u+x / chmod 755 / chmod -R
├─ 改属主：chown user:group / chgrp
└─ 特殊位：setuid(4) / setgid(2) / sticky(1)，如 /tmp 的 1777

通关自测

Q1root 的 UID 是多少？
答：0。
Q2-rwxr-xr-- 对应的数字权限是多少？
答：754（rwx=7，r-x=5，r--=4）。
Q3为什么给目录的执行权限很重要？
答：没有 x 不能进入目录，也不能访问目录里的文件，即使文件本身有权限。
Q4usermod -G dev tom 和 usermod -aG dev tom 有什么区别？
答：前者会把 tom 的附加组覆盖成只有 dev；后者是追加，保留原有附加组。
Q5chmod 777 为什么通常不推荐？
答：所有用户都能读、写、执行，安全风险大；应最小权限。
Q6setuid 和 sticky 各有什么典型用途？
答：setuid 让程序以属主身份运行（如 passwd）；sticky 让 /tmp 下只有文件属主能删自己的文件。
