5-01

实战章节：前言

一句话核心实战部署要先把“机器、目录、端口、版本、快照”规划好，再按“装、配、启、验、排”五步执行；不要上来就敲命令。

本节要解决的问题

从这一节开始，你不再只是学单个命令，而是完成一个又一个真实部署。部署最怕“边装边想”，先规划能省掉一半的坑。

核心概念（小白也能懂）

部署
把软件装到服务器、改好配置、启动服务、验证可用，并知道出问题怎么查。
节点
集群里的一台服务器；课程用 3 台虚拟机模拟 hadoop1/hadoop2/hadoop3。
端口规划
提前分配每个软件用的端口，避免 8080/8081 这类冲突。
基线快照
装好系统、配好网络后拍的干净快照，后面每装一个大软件前再拍一次。

拆开讲

建议环境：CentOS 7，3 台虚拟机，每台 2 核 4 GB（至少 2 GB）、40 GB 磁盘；IP 规划为 192.168.10.101/102/103，hostname 为 hadoop1/2/3，网关 192.168.10.2。

目录规划：安装包放 /opt/software，解压后的软件放 /opt/module 或 /opt/软件名，数据放 /data 或 /opt/软件名/data。统一目录，后面写文档、迁移、备份都方便。

部署五步法：装（yum/rpm/tar）、配（改配置文件）、启（systemctl 或启动脚本）、验（端口、进程、页面、日志）、排（看日志、查端口、查权限、查依赖）。每一步都留下记录。

每装完一个软件，先 jps/ss -lntp/curl 验证，再拍快照。不要一口气装五个，最后不知道是谁坏了。一次只动一个变量，排错才快。

5-02

MySQL 5.7 在 CentOS 安装（单机软件）

一句话核心CentOS 装 MySQL 5.7：卸 MariaDB → 装依赖 → 解压 RPM bundle → 按 common/libs/client/server 顺序安装 → 启动 → 用临时密码改密 → 配字符集/远程授权。

本节要解决的问题

MySQL 是后面很多应用的基础。装 MySQL 的坑集中在：MariaDB 冲突、RPM 依赖顺序、临时密码、密码策略、远程授权。按顺序来就不乱。

核心概念（小白也能懂）

MariaDB
MySQL 的分支，CentOS 7 默认可能预装，会和 MySQL 冲突，先卸载。
RPM bundle
MySQL 官方把 common/libs/client/server 等打成一包 tar，里面是多个 rpm。
临时密码
MySQL 5.7 首次启动生成在 /var/log/mysqld.log，用 grep temporary password 找。
validate_password
密码强度插件；学习环境可降低策略，生产不要。

拆开讲

先卸载 MariaDB：rpm -qa | grep mariadb 找到包名，rpm -e --nodeps mariadb-libs-...。--nodeps 是强制卸载，可能影响依赖，学习环境可接受；生产要评估。

安装依赖 libaio、numactl，解压 bundle 到 /opt/mysql。按顺序 rpm -ivh mysql-community-common-*.rpm → libs → client → server。如果报依赖 libs-compat，再装 mysql-community-libs-compat。

启动 systemctl start mysqld，systemctl enable mysqld。首次启动日志里有临时密码：grep 'temporary password' /var/log/mysqld.log。用它登录后立刻 ALTER USER 'root'@'localhost' IDENTIFIED BY 'Root@123456';。

改 /etc/my.cnf：character-set-server=utf8、default-storage-engine=INNODB、validate_password_policy=0、validate_password_length=4，重启生效。然后授权远程：GRANT ALL PRIVILEGES ON *.* TO 'root'@'%' IDENTIFIED BY 'Root@123456' WITH GRANT OPTION; FLUSH PRIVILEGES;。

  3. systemctl start mysqld && systemctl enable mysqld。

  6. 创建远程 root 授权，放行 3306，客户端测试连接。

小白避坑

  • MariaDB 没卸干净，MySQL 装完启动失败/端口冲突。
  • rpm 安装顺序错，报依赖错误；按 common→libs→client→server。
  • 找不到临时密码：日志路径不对/首次启动失败，先看 systemctl status mysqld。
  • 密码太简单被策略拒绝；先改策略再改密码。
  • 只授权 localhost，远程连不上；要 'root'@'%' 并放行防火墙。
记忆口诀“卸 Maria、装依赖、按序 rpm；找临时密码、改策略、开远程。”

5-03

MySQL 8.0 在 CentOS 安装（单机软件）

一句话核心MySQL 8.0 安装流程和 5.7 类似，但默认认证插件是 caching_sha2_password，密码策略变量名也变了；远程授权建议先 CREATE USER 再 GRANT。

本节要解决的问题

8.0 是现在的主流，但老客户端/老代码可能不认新认证插件。装的时候要理解“认证插件”和“密码策略”这两个差异。

核心概念（小白也能懂）

caching_sha2_password
MySQL 8 默认认证插件，比 mysql_native_password 更安全，但老客户端可能不支持。
mysql_native_password
旧认证插件，兼容性好；必要时可为用户切换，但不建议全局长期使用。
validate_password
8.0 的密码策略变量是 validate_password.policy、validate_password.length。
RPM 依赖
8.0 bundle 可能还需要 client-plugins、icu-data-files、libs-compat。

拆开讲

卸载 MariaDB，安装 libaio、numactl；解压 8.0 bundle 到 /opt/mysql8。按 common → client-plugins → libs → client → server（必要时 icu-data-files、libs-compat）顺序安装。

启动 mysqld，找临时密码，登录后 ALTER USER 'root'@'localhost' IDENTIFIED BY 'Root@123456';。8.0 默认密码策略较严，学习环境可在 /etc/my.cnf 设 validate_password.policy=LOW、validate_password.length=4。

远程授权：先 CREATE USER 'root'@'%' IDENTIFIED WITH mysql_native_password BY 'Root@123456';，再 GRANT ALL PRIVILEGES ON *.* TO 'root'@'%' WITH GRANT OPTION; FLUSH PRIVILEGES;。如果客户端支持新插件，也可以不指定 WITH mysql_native_password。

字符集建议 utf8mb4（支持 emoji），排序规则 utf8mb4_general_ci 或 utf8mb4_0900_ai_ci。改完重启，用 SHOW VARIABLES LIKE 'character_set_server'; 验证。

  2. 解压 8.0 bundle，按顺序安装 RPM。
  3. 启动 mysqld，找临时密码并改密。
  4. 配置 my.cnf：utf8mb4、密码策略、认证插件。
  5. 创建远程用户并授权。
  6. 放行 3306，用客户端连接验证。

小白避坑

  • 老客户端连 8.0 报 “Authentication plugin 'caching_sha2_password' cannot be loaded”；为该用户切 mysql_native_password。
  • 密码策略变量写成 5.7 的 validate_password_policy，8.0 不生效。
  • 只 GRANT 不 CREATE USER，8.0 可能报用户不存在。
  • 升级/混装 5.7 和 8.0 的 RPM，依赖冲突。
  • 字符集还用 utf8，存 emoji 失败；用 utf8mb4。
记忆口诀“8.0 两处不一样：认证插件 caching_sha2，密码策略带点号；远程先建用户再授权。”

5-04

MySQL 5.7 在 Ubuntu 安装（单机软件）

一句话核心Ubuntu 装 MySQL 5.7 主要用 deb bundle + dpkg，按 common→client→server 顺序装，依赖用 apt -f install 补；Ubuntu 的 root 常用 auth_socket。

本节要解决的问题

Ubuntu 的包格式是 deb，不是 rpm。命令和路径都变了，但“装、配、启、验”的思路完全一样。

核心概念（小白也能懂）

deb bundle
MySQL 官方为 Ubuntu 提供的 tar 包，里面是多个 .deb 文件。
dpkg
Debian 系底层包工具，装本地 deb，不自动解决依赖。
auth_socket
Ubuntu 的 MySQL root 常通过系统 root 身份认证，sudo mysql 可直接进。
bind-address
MySQL 监听地址，默认 127.0.0.1，改成 0.0.0.0 才能远程。

拆开讲

先 apt update，安装 libaio1、libnuma1 等依赖。解压 deb bundle，按 mysql-common → mysql-community-client → mysql-client → mysql-community-server → mysql-server 顺序 dpkg -i；缺依赖时 apt -f install。

启动 systemctl start mysql，systemctl enable mysql。Ubuntu 的 root 可能用 auth_socket，直接 sudo mysql 进入，然后 ALTER USER 'root'@'localhost' IDENTIFIED WITH mysql_native_password BY 'Root@123456';。

远程访问：改 /etc/mysql/mysql.conf.d/mysqld.cnf 的 bind-address = 0.0.0.0，重启；创建 'root'@'%' 并授权；ufw allow 3306/tcp。

Ubuntu 18.04 官方源默认 MySQL 5.7，20.04 默认 8.0。装 5.7 需要对应版本的 deb 包，别把 18.04 的包硬装到 22.04 上，依赖可能不兼容。

5-05

MySQL 8.0 在 Ubuntu 安装（单机软件）

一句话核心Ubuntu 装 MySQL 8.0 最简单：apt install mysql-server；用 sudo mysql 进去改 root 认证/密码，再改 bind-address、建远程用户、放行 ufw。

本节要解决的问题

这是几条 MySQL 安装路线里最省事的一条。省事不等于没坑：root 认证、bind-address、密码策略、远程授权仍然要会。

核心概念（小白也能懂）

apt 源
Ubuntu 官方源自带 MySQL 8.0，直接 apt 安装，自动解决依赖。
mysql_secure_installation
交互式安全脚本：删匿名用户、禁 root 远程、删 test 库、刷新权限。
auth_socket
root 通过系统用户身份认证；改密码后可用密码登录。
ufw
Ubuntu 的防火墙工具，ufw allow 3306/tcp 放行。

拆开讲

sudo apt update && sudo apt install -y mysql-server，安装完 systemctl status mysql 确认 running。默认 root 可能使用 auth_socket，sudo mysql 可直接进入。

改 root 密码/插件：ALTER USER 'root'@'localhost' IDENTIFIED WITH mysql_native_password BY 'Root@123456'; FLUSH PRIVILEGES;。然后可以运行 sudo mysql_secure_installation 做安全加固。

核心概念（小白也能懂）

Elasticsearch
分布式搜索和分析引擎，常用于全文检索、日志（ELK）。

vm.max_map_count

本节要解决的问题

核心概念（小白也能懂）

hosts 映射

SELinux

时间同步

scp 命令

一句话核心scp 基于 SSH 安全复制文件：scp 源 目标，目录加 -r，非 22 端口用 -P；集群里常用 for 循环批量分发。

本节要解决的问题

集群有 3 台机器，装好的软件/配置要同步到每台。逐个传太慢，scp + for 循环是基础自动化。

核心概念（小白也能懂）

scp
secure copy，基于 SSH 的远程复制，语法和 cp 类似。
远程路径
格式 用户@主机:路径，如 root@hadoop2:/opt/。
-r / -P
-r 递归目录；-P 指定 SSH 端口（大写）。
批量分发
用 for 循环遍历主机名，把同一份文件发到各节点。

拆开讲

本机→远程：scp file root@hadoop2:/opt/；远程→本机：scp root@hadoop2:/opt/file .；目录：scp -r /opt/module root@hadoop2:/opt/；端口：scp -P 2222 file root@hadoop2:/opt/。

批量分发：for host in hadoop1 hadoop2 hadoop3; do scp -r /opt/module/xxx root@$host:/opt/module/; done。前提是已配免密，否则每次都输密码。

如果目标目录已存在同名目录，scp -r 可能把源目录放到目标里面，路径多一层。分发前先确认目标路径，必要时先删除/备份。

大量文件/需要增量同步用 rsync -avz --progress 源 目标；scp 每次全量复制，断了大文件要重传。

命令/操作速查

scp 常用写法

命令作用
scp file root@hadoop2:/opt/传文件
scp -r dir root@hadoop2:/opt/传目录
scp root@hadoop2:/opt/file .下载到当前目录
scp -P 2222 file root@hadoop2:/opt/指定端口
for h in hadoop1 hadoop2 hadoop3; do scp -r dir root@$h:/opt/; done批量分发
rsync -avz dir/ root@hadoop2:/opt/dir/增量同步（扩展）

动手做

  1. 确认三台已配 SSH 免密。
  2. 把单个文件 scp 到 hadoop2，验证。
  3. 把目录 scp -r 到 hadoop3，验证内容。
  4. 用 for 循环把配置分发到三台。
  5. 用 md5sum 对比源/目标文件一致性。

代码/配置参考

  scp -r /opt/module/hadoop root@$host:/opt/module/
done

ssh hadoop2 md5sum /opt/module/hadoop/etc/hadoop/core-site.xml

小白避坑

  • scp -P 写成 -p，-p 是保留时间/权限，不是端口。
  • 目标路径末尾斜杠/不斜杠导致目录嵌套层级不同。
  • 没配免密，for 循环每个节点都卡在输密码。
  • 用 root 分发后文件属主全变 root，服务用户读不了；必要时 chown。
  • 大文件用 scp 中断要重传；用 rsync。
记忆口诀“scp 像 cp，远程写 user@host:path；目录 -r，端口大写 P，批量用 for。”

Zookeeper 安装部署（集群化软件）

一句话核心Zookeeper 集群：每台装 JDK + 解压 ZK → zoo.cfg 配 dataDir/clientPort/server.N → data/myid 写本机编号 → 三台启动 → zkServer.sh status 看 Leader/Follower。

本节要解决的问题

ZK 是分布式协调组件，Kafka、HBase 都依赖它。ZK 集群的坑集中在 myid、server 列表、端口、防火墙。

核心概念（小白也能懂）

Zookeeper
分布式协调服务，提供配置管理、命名、分布式锁、选主。
myid
每个节点的唯一编号，必须和 zoo.cfg 里 server.N 的 N 对应。
Leader/Follower
ZK 集群角色；写请求走 Leader，Follower 参与投票/读。
2888/3888
ZK 集群内部通信/选举端口。

拆开讲

三台都装 JDK 8。下载 apache-zookeeper-3.7.x-bin.tar.gz，解压到 /opt/module/zookeeper。注意要下载 -bin 包，纯源码包不能直接跑。

conf/zoo.cfg 关键：tickTime=2000、initLimit=10、syncLimit=5、dataDir=/opt/module/zookeeper/data、clientPort=2181，以及三行 server.1=hadoop1:2888:3888、server.2=hadoop2:2888:3888、server.3=hadoop3:2888:3888。

每台创建 dataDir，写 myid：hadoop1 写 1，hadoop2 写 2，hadoop3 写 3。myid 内容只能是数字，不能有多余空格/换行内容。

启动：bin/zkServer.sh start，bin/zkServer.sh status 看 Mode（一个 leader、两个 follower）。bin/zkCli.sh -server hadoop1:2181 进客户端，ls / 验证。三台都启动后再看状态，只起一台可能选不出 leader。

Kafka 集群部署（集群化软件）

一句话核心Kafka 旧架构依赖 Zookeeper：先起 ZK → 每台配 broker.id/listeners/advertised.listeners/log.dirs/zookeeper.connect → 启动 → 建 topic → 生产/消费验证。

本节要解决的问题

Kafka 是分布式消息队列。它不难装，难在 advertised.listeners：配错时本机通、远程客户端连不上。

核心概念（小白也能懂）

Broker
Kafka 服务节点，每个 broker 有唯一 broker.id。
Topic/Partition
消息主题，分区提高并行度；副本提高可靠性。
advertised.listeners
告诉客户端“应该用哪个地址连我”，集群/远程访问必须配。
Zookeeper
旧版 Kafka 用 ZK 存元数据、做选主；ZK 必须先启动。

拆开讲

启动：bin/kafka-server-start.sh -daemon config/server.properties；jps 应看到 Kafka；ss -lntp | grep 9092。停止：bin/kafka-server-stop.sh。

建 topic：bin/kafka-topics.sh --bootstrap-server hadoop1:9092 --create --topic test --partitions 3 --replication-factor 2；查看：--list、--describe。

生产/消费：kafka-console-producer.sh --bootstrap-server hadoop1:9092 --topic test；另开终端 kafka-console-consumer.sh --bootstrap-server hadoop1:9092 --topic test --from-beginning。

HBase 集群部署（集群化软件）

一句话核心HBase 依赖 HDFS + Zookeeper：配 hbase.rootdir/hbase.cluster.distributed/hbase.zookeeper.quorum → regionservers → start-hbase.sh → jps/HMaster、HRegionServer → 16010/ shell 验证。

本节要解决的问题

HBase 是建立在 HDFS 上的列式数据库。装它之前，HDFS 和 ZK 必须正常，否则 HBase 起来也会马上挂。

核心概念（小白也能懂）

HBase
分布式列式数据库，适合海量稀疏数据，底层存 HDFS。
HMaster/HRegionServer
HBase 主节点/区域服务器，类似 NameNode/DataNode 的角色。
rootdir
HBase 在 HDFS 上的根目录，如 hdfs://hadoop1:8020/hbase。
regionservers
HBase 从节点列表，写 RegionServer 主机名。

拆开讲

前置：HDFS 正常、ZK 正常、三台时间同步。解压 HBase 到 /opt/module/hbase，配 HBASE_HOME/PATH。

conf/hbase-site.xml：hbase.rootdir=hdfs://hadoop1:8020/hbase、hbase.cluster.distributed=true、hbase.zookeeper.quorum=hadoop1,hadoop2,hadoop3、hbase.zookeeper.property.dataDir=/opt/module/zookeeper/data、hbase.master.info.port=16010。

conf/regionservers 写 hadoop1/2/3（或只写从节点）。把配置分发到三台。启动 start-hbase.sh；jps 看 HMaster/HRegionServer；UI http://hadoop1:16010。

hbase shell 验证：status、list、create 'test','cf'、put 'test','row1','cf:name','tom'、scan 'test'。

Spark 分布式内存计算集群部署（集群化软件）

一句话核心Spark 集群：JDK/Hadoop 就绪 → 解压 → spark-env.sh 配 JAVA_HOME/HADOOP_CONF_DIR/MASTER_HOST → workers → start-all.sh → Master/Worker 进程和 8080/8081 页面。

本节要解决的问题

Spark 是内存计算框架，常跑在 YARN 或独立集群上。课程用 Standalone 模式，先理解 Master/Worker 架构。

核心概念（小白也能懂）

Spark
分布式内存计算框架，适合批处理、SQL、流计算、机器学习。
Standalone
Spark 自带的集群模式，Master 管资源，Worker 跑 Executor。
spark-env.sh
Spark 环境配置，配 JAVA_HOME、HADOOP_CONF_DIR、Master 地址。
spark-shell
交互式 Scala Shell，验证集群是否可用。

拆开讲

前置：JDK 8、Hadoop（可选但建议）、三台免密。解压 Spark 到 /opt/module/spark，配 SPARK_HOME/PATH。

conf/spark-env.sh（从 template 复制）：JAVA_HOME=...、HADOOP_CONF_DIR=/opt/module/hadoop/etc/hadoop、SPARK_MASTER_HOST=hadoop1、SPARK_MASTER_PORT=7077、SPARK_WORKER_CORES=2、SPARK_WORKER_MEMORY=2g。

conf/workers 写 hadoop2/hadoop3（或包含 hadoop1）。分发配置。start-all.sh 启动；jps 在 hadoop1 看 Master，在 worker 看 Worker。UI：Master http://hadoop1:8080，Worker http://hadoop2:8081。

验证：spark-shell --master spark://hadoop1:7077，执行 sc.parallelize(1 to 10).sum()。提交任务：spark-submit --master spark://hadoop1:7077 --class ... app.jar。

Flink 分布式内存计算集群部署（集群化软件）

一句话核心Flink 集群：JDK → 解压 → flink-conf.yaml 配 JobManager 地址/slot/并行度 → masters/workers → start-cluster.sh → 8081 UI → flink run 提交任务。

本节要解决的问题

Flink 是流式计算框架，和 Spark 一样是内存计算，但更偏实时流。装法与 Spark 类似，重点在 JobManager/TaskManager 的配置。

核心概念（小白也能懂）

Flink
分布式流处理框架，支持事件时间、状态、Exactly-Once。
JobManager/TaskManager
JM 管作业调度/检查点，TM 提供 slot 执行任务。
TaskSlot
TaskManager 的资源槽，决定单节点能并行跑多少任务。
flink-conf.yaml
Flink 1.x 主配置；新版本可能改为 config.yaml。

拆开讲

前置：JDK 8、三台免密、hosts。解压 Flink 到 /opt/module/flink，配 FLINK_HOME/PATH。

conf/flink-conf.yaml：jobmanager.rpc.address: hadoop1、jobmanager.rpc.port: 6123、taskmanager.numberOfTaskSlots: 2、parallelism.default: 2、jobmanager.memory.process.size: 1024m、taskmanager.memory.process.size: 2048m。

conf/masters 写 hadoop1:8081；conf/workers 写 hadoop2/hadoop3（或含 hadoop1）。分发配置。start-cluster.sh 启动；jps 看 StandaloneSessionClusterEntrypoint（JM）和 TaskManagerRunner（TM）。

UI http://hadoop1:8081。提交示例：flink run -c org.apache.flink.streaming.examples... examples/streaming/WordCount.jar；或 flink run -m hadoop1:8081 app.jar。

通关自测

Q1部署一套软件的五个步骤是什么？
答：装、配、启、验、排（安装、配置、启动、验证、排错）。
Q2MySQL 5.7 和 8.0 在远程授权上的主要区别？
答：5.7 可用 GRANT ... IDENTIFIED BY；8.0 推荐先 CREATE USER ... IDENTIFIED WITH mysql_native_password BY 再 GRANT。
Q3Elasticsearch 为什么不能用 root 启动？
答：ES 出于安全考虑禁止 root 运行，需创建普通用户并 chown 目录。
Q4Hadoop 格式化 NameNode 为什么只能做一次？
答：格式化会重建元数据，已有数据目录可能被清空/不一致，导致数据丢失。
Q5Kafka 启动前为什么先启动 Zookeeper？
答：旧版 Kafka 依赖 ZK 存元数据、做 broker 协调；ZK 没起，Kafka 会报连接失败。
Q6Spark 和 Flink 的 UI 端口可能和谁冲突？
答：Spark Master 8080 可能与 Tomcat 冲突；Spark Worker/Flink 8081 可能互相冲突。
